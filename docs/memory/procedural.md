# Как делать

Рабочие процедуры фабрики: пайплайны, порядок коммита, разведка, лимиты.

---

2026-09-28 | Одна инструкция — один шаг
Задание капитана исполняется как последовательность шагов без смешивания: разведка отдельно, запись отдельно, верификация отдельно. Если шаг требует решения капитана — остановка до approve, а не «додумывание» за него.

2026-09-28 | «Не на веру»: каждый факт со ссылкой
Любая находка подтверждается ссылкой на файл+строку или на git-SHA. Без ссылки это гипотеза, и в решения она не идёт — в отчёте она помечается как «не установлено». Пути не угадываются: искать через `git ls-files`, дерево каталогов, `package.json`.

2026-09-28 | Time-box
Разведка — 20 минут, исполнение — 30–60 минут. Упёрся в лимит: фиксирую «не установлено», останавливаюсь, отчитываюсь — без попыток «дожать» любой ценой. Провальные попытки считаются: 3 неудачи по одной задаче → задача отклоняется и фиксируется как налог (стоп-кран плана, ЧАСТЬ 6).

2026-09-28 | Разведка: read-only отчёт → стоп → approve → действие
Сначала только чтение: собрать факты, показать отчёт капитану, остановиться. Запись начинается только после явного approve. Смешивать разведку и запись в одном шаге запрещено — иначе откат невозможен без грязи в дереве.

2026-09-28 | Порядок коммита
`npm run sync` → `git add` **явными путями** (никаких `git add .` / `-A`) → `git commit` → `npm run sync:check` (exit 0 = done). Красный check — не «починить любой ценой», а `sync` + новый коммит; постоянное расхождение фиксируется как налог правила 9. Push — только отдельная per-command авторизация капитана (правила 10/11). Контент банка оркестратору без approve капитана коммитить нельзя.

2026-09-28 | Пайплайн контента: Writer → QC → preview → approve → commit
1. Writer пишет кандидатов (в `.project/drafts/*-candidates.json`, счётчик и id-диапазон сверяются с конвенцией темы).
2. QC по правилам `tools/qc.cjs` — оффлайн-пречек черновика **до** любой записи в `src/data/` (дескриптор для этого — `qc-preview-check.mjs`, копия правил qc).
3. Соседи и дубли: `node .project/drafts/batch-*-neighbors.mjs <candidates.json>` (max cos), при долге — `tools/cosine.cjs --intra-batch`; Haladyna — `node tools/haladyna.cjs --batch <candidates.json>`.
4. Превью — `.project/drafts/batch-*-preview.md` (8 разделов) и показать капитану.
5. Approve капитана обязателен всегда для `type=content` (правило 6: автономия на контент не распространяется).
6. Интеграция: дописать вопросы в конец `src/data/questions/<topic>.json`, обновить `_order.json` (**`npm run order:add <id>`** / `npm run order:remove <id>`; сверка — `npm run order:check`, spec 032 — ручная правка больше не нужна), `npm run manifest`, `npm run shuffle-bank:check`, `npm run qc`, затем коммит.

2026-09-29 | Manual-файлы и self-reference
Manual-файлы (`working.md` — не пишется sync; `alerts.md`/`procedural.md` — тоже manual, sync их только читает) обновляются с SHA предыдущего коммита. Отставание на 1 коммит допустимо (f4-checker). Если manual-файл коммитится после converge — следующий `sync` даст drift; лечится `git checkout --` на производные. Правило: писать manual-файл ДО converge. НЕ обновлять manual-файл в одном batch с несколькими коммитами (лаг > 1 коммита — семантически неверен); либо обновлять его ПОСЛЕ всех коммитов отдельным, либо оставить на следующий batch.

2026-09-29 | Time-box (уточнение). Превышение оценки — СТОП, не дожатие.
Прецедент C2a-3: оценка 40 строк, реализовано 53 (26 — комментарий). Агент не СТОПнулся, дожал. Результат корректный, капитан принял. Но по прецеденту F2.3 (закрытый): при превышении стоп-условия — СТОП и отчёт, а не дожимание. Уточнение к разделу «Time-box»: превышение обосновано (комментарии, документация) — фиксировать в отчёте явно, но СТОП всё равно предпочтителен. Следующий раз — СТОП.

2026-09-30 | EPERM `agent_teams_delete` — архивация вне плагина хелпером
Плагин `agent_teams_delete()` падает с `EPERM ... rename '.agent-teams/<teamId>' -> '.agent-teams/archive/<teamId>'` (spec-030, spec-031): причина не в правах, а в открытом дескрипторе ниже переименовываемого каталога без `FILE_SHARE_DELETE` (живой подпроцесс сессии/ящик команды, скан AV, индексатор) — такой rename на Windows не проходит; плагин повторяет 3×50 мс (`lib/state.js:508-510,802-816`) и сдаётся раньше, чем дескриптор освободится.
Архивировать каталог команды хелпером вне плагина: `node .project/scripts/archive-team.mjs <teamId>` (окно ожидания, backoff, idempotent: уже в `archive/` → no-op); `--check` — только статус, `--dry-run` — без изменений, `--timeout-ms` — окно; exit 3 = дескриптор держится, в выводе причина и кандидаты-файлы.
Процедура: вызывать ПОСЛЕ завершения сессии и подпроцессов команды; при exit 3 — закрыть сессию DSH, подождать, повторить (хелпер идемпотентен). Мгновенный rename каталога на месте (в `<teamId>` и обратно) — безопасная read-only проба «дескрипторов сейчас нет»: на `spec-030`/`spec-031` она проходит, значит удержание транзиентное, а не постоянное свойство каталога.

2026-10-02 | Playwright E2E — только для `type: feature` / `type: ui`
Обязательный Playwright-гейт (SKILL Шаг 4b: `npx playwright install chromium` → `npm run test:e2e`, CLI, не MCP) запускается **только** для спек `type: feature` / `type: ui`. Для `infra` / `docs` / `content` E2E-прогон не запускать без отдельного обоснования капитана: набор `e2e/**` проверяет UI-потоки приложения, и его дрейф делает гейт красным по причине, не относящейся к предмету такой спеки. Прецедент spec 048 (infra): t6 `npm run test:e2e` = 1 в трёх прогонах из-за фикстур `fp_001..fp_012` против живых 19 вопросов `file_permissions` — дрейф зафиксирован в `alerts.md` 2026-10-02 и признан out-of-scope; спека закрыта по вердикту t5 (reviewer, verdict=pass). Правила 3, 16.
