## Пересечение

Сабтопики, которые тема `text_files` (по текущему `description`) заявляет, но которые **уже покрыты другими темами**:

| заявлено в `description` `text_files` | где уже покрыто | конкретные id |
|---|---|---|
| `cp` / `mv` | `file_management` (`cp / mv / ln (symbolic vs hard)`) | `fm_001`, `fm_006` |
| hard/soft links | `file_management` (тот же сабтопик) | `fm_012` |
| `permissions` | `file_permissions` (12 вопросов темы, домен 9) | `fp_001..fp_012` (вся тема) |
| — (сверх этого) текстовая обработка | `essential_tools` | `et_001` (grep -F), `et_003` (sort -n), `et_007` (grep -c) |
| — (сверх этого) перенаправления | `file_management` | `fm_005` (redirection: `>`, `>>`, `2>&1`, `tee`) |

Дополнительно: `essential_tools` в `topics.ts:29` заявляет `grep` в своём `description` ('shell, grep, ssh, tar, man pages'), а `file_management` в `topics.ts:23` — `redirection`. То есть два из четырёх «текстовых» сабтопиков уже явно приписаны другим темам на уровне их собственных описаний.

Обратное пересечение: `file_management` заявляет `find`, `tar`, `links` — к текстовой обработке не относятся; `essential_tools` заявляет `ssh`, `man pages` — тоже. Пересечение одностороннее: `text_files` почти целиком лежит внутри уже занятых областей.

## Три варианта (не выбирать, не рекомендовать, только описать)

### Вариант A — переименовать тему

- Новое название: `Работа с текстовыми файлами` (или `Текстовые утилиты`).
- Обоснование: одна строка — текущий `title` уже описывает обработку текста, поэтому меняется не смысл, а точность формулировки и `key`.
- Что делать с `description`: заменить на перечень именно текстовых утилит, например `'grep, sed, awk, cut, sort, uniq, tr, vim, nano'` — то есть убрать из него `cp, mv, hard/soft links, permissions`, которые к тексту не относятся.
- Влияние на план вопросов: пишутся новые сабтопики `sed`/`awk`/`cut`/`uniq`/`tr`/`vim` (в банке их нет: `git grep -i "sed\|awk"` по репо дал только совпадения внутри слов вроде `randomised`, `pooling`), но часть потенциальных слотов придётся сознательно исключить, чтобы не дублировать `et_001`/`et_003`/`et_007` (grep, sort) и `fm_005` (redirection). В `topics.ts` меняются `key` (влияет на 8 planned-тем? нет — только на эту: `key` используется в `filterByTopic`/`startTopicQuiz`) и `description`; тема остаётся `planned`.

### Вариант B — переопределить содержание темы

- Название оставить: `Работа с текстом`.
- `description` заменить на: `'sed, awk, cut, sort -u, uniq, tr, tee, vim-навигация, поиск по файлам'`.
- Какие сабтопики писать (5–7):
  1. `sed: подстановка и удаление строк`
  2. `awk: выбор полей и печать колонок`
  3. `cut: выбор полей и диапазонов`
  4. `uniq / sort -u: дедупликация`
  5. `tr: преобразование регистра и удаление символов`
  6. `tee: запись потока в файл и на экран`
  7. `vim: базовые операции (открыть, сохранить, поиск, замена)`
- Обоснование: одна строка — тема становится полностью непересекающейся, потому что `sed`/`awk`/`cut`/`uniq`/`tr`/`vim` в банке отсутствуют, а `grep`/`sort -n`/`redirection` остаются у `essential_tools` и `file_management`.
- Побочный эффект: `description` перестаёт упоминать `cp/mv/links/permissions`, поэтому пересечение с `file_management` и `file_permissions` формально исчезает, но фактическое дублирование слотов (если автор возьмёт общую «файловую» тему) не исключено — см. «Открытые вопросы».

### Вариант C — слить с другой темой

- С какой: `file_management` (у `essential_tools` уже заняты `grep`/`ssh`/`man pages`, а `file_management` уже содержит `cp`/`mv`/`links`/`redirection` — то есть 3 из 4 заявленных сабтопиков этой темы).
- Как: убрать `text_files` из `TOPICS` в `topics.ts` (14 тем → 13, planned 8 → 7), а текстовую обработку (`sed`/`awk`/`cut`/`uniq`/`tr`) писать новыми сабтопиками внутри `file_management`, увеличив её целевой объём. `filterByTopic`/`startTopicQuiz` работают по `key`, поэтому удаление ключа ничего не ломает, пока в банке нет ни одного вопроса с `topic: 'text_files'` (сейчас их 0 — подтверждено `STATE-SNAPSHOT-2026-09-24.md:288` и `git grep "text_files"`).
- Что теряем: отдельную карточку темы в UI (Dashboard рендерит темы из `TOPICS`), отдельный счётчик прогресса и возможность точечного topic-quiz по текстовой обработке; при этом теряется и «домен-привязка» — если `text_files` действительно должен быть доменом 5 (цитата из `report-2026-09-22.md:82`), слияние с `file_management` смешает два домена в одной теме (`file_management` в банке представлена доменами 1, 4, 5 — см. `objective_domain` у `fm_001..fm_012`).

## Открытые вопросы к капитану

1. `text_files` должен относиться к домену 5 или к домену 1? Единственная зацепка — `drafts/report-2026-09-22.md:82` («по разведке относится к домену 5»), но документа с целями домена 5 в репо нет — подтвердить можно только внешним источником.
2. Нужна ли в банке отдельная тема под shell-скрипты (домен 2 EX200 сейчас 0 вопросов, `shell_scripts` — `planned`)? Если да, не стоит ли `text_files` объединить именно с ней, а не с `file_management`, поскольку `sed`/`awk` — это в первую очередь инструменты скриптов?
3. Допустимо ли, чтобы `grep` и `sort` оставались в `essential_tools`, а `redirection` — в `file_management`, при том что текстовые сабтопики новой темы будут тематически смежными? Или требуется жёсткая непересекающаяся таксономия (тогда нужна ревизия всех трёх описаний: `file_management`, `essential_tools`, `text_files`)?
4. Что первично при наполнении: закрыть домен 2 (0 вопросов) или домен 5 (4 вопроса), если ресурс ограничен одной темой на итерацию?
