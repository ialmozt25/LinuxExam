# LinuxExam — цели проекта

Источник правды по целям. Все milestones и решения сверяются с этим документом.

## Северная звезда
> Время от начала новой сессии до полного понимания состояния проекта — <= 3 минуты.

Всё остальное — инструменты достижения этой метрики.

## 1. Продуктовая цель
Создать веб-тренажёр для подготовки к RHCSA EX200.
- Аудитория: начинающие и средние Linux-администраторы.
- Целевой объём: банк 300+ вопросов (сейчас 160).
- Формат: MCQ, 4 опции, UI на русском.
- Монетизация: Telegram-бот @linux_exam_bot, Telegram Stars.
- Прод: https://ialmozt25.github.io/LinuxExam/

Метрика успеха: 300+ валидных вопросов + работающая монетизация.

## 2. Процессная цель
Перейти от хаотичных сессий к управляемой, повторяемой, масштабируемой
разработке через MAS.
- Каждая роль — отдельный пресет DSH (Orchestrator -> Content Writer -> QC -> ...).
- Handoff между агентами через явные контракты (Agent Contracts).
- Каждый запуск воспроизводим.
- Human-in-the-loop: капитан сохраняет контроль над решениями.

Метрика успеха: новая сессия даёт одинаковый контекст за <= 3 минуты;
агенты не теряют цель при handoff.

## 3. Инфраструктурная цель
Построить локальный центр разработки — веб-приложение с дашбордами.
- Модули: Overview, Agents, MAS Flow, Decisions, Blockers, Ideas.
- Настройка через JSON-конфиг, а не хардкод.
- Переиспользуемость: ядро выносится в отдельный пакет.
- База знаний docs/knowledge/ + библиотека паттернов patterns/.

Метрика успеха: центр разворачивается за один вечер на новом проекте;
>= 5 паттернов переиспользуемы.

## 4. Метацель
Перестать терять контекст и вернуть капитану контроль над разработкой.
- Боль: не успеваю читать отчёты, теряется контекст, нет контроля.
- Решение: .project/ как единый источник правды + протокол агента
  (Bootstrap -> Work -> Report -> Handoff).
- M0.7.1 (отложено): автоматизация моста браузерного чата с DSH —
  при триггере >= 3 итераций ручного копипаста.

Метрика успеха: капитан не тратит время на перенос инструкций и поиск
«где мы сейчас».

## Что важно не потерять
1. Мы строим не «дашборд», а систему контроля. Дашборд — визуализация
   над .project/. Если данные в файлах неверны — дашборд будет врать.
2. Мы строим MAS по мере роста, а не заранее. Новая роль добавляется
   только при триггере.
3. Мы строим переиспользуемое, а не только LinuxExam. patterns/,
   docs/knowledge/, ядро центра — всё это пойдёт в следующий проект.
4. Монетизация — критический блокер продукта. Всё сейчас —
   инфраструктура; деньги — в M5.
