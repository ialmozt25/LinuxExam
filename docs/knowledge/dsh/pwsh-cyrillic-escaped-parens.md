# DSH: pwsh + Cyrillic + экранированные скобки в regex

Дата: 2026-09-26
Контекст: M2.2c-4, замена шапки agent.cordis.yml QC-пресета.

## Проблема

Команды pwsh, содержащие одновременно:
- двойные кавычки ("..."),
- экранированные скобки в regex (\( или \)),
- кириллицу,

возвращают ПУСТОЙ вывод и exit code 1, без текста ошибки. Парсер сообщает
"missing closing '". Диагностика через $Error не помогает.

Примеры, которые падают:
  $pattern = "\(Content Writer не делегирует\)"
  if ($text -match "\(Content Writer не делегирует\)") { ... }

## Причина

Взаимодействие экранирования внутри двойных кавычек и кириллических символов
в парсере pwsh 7.6.6. Точный механизм не установлен.

## Обход

1. Использовать single-quoted строки '...' или here-string @'...'@ —
   они не интерполируют и не обрабатывают экранирование.
2. Использовать .Replace() / .Contains() вместо regex, если возможно.
3. Использовать [regex]::Escape($literal) — экранирование делает платформа.
4. Если ничего не помогает — записать команду в %TEMP%\fix.ps1 (ВНЕ репо),
   вызвать через & "$env:TEMP\fix.ps1", удалить после.

## Проверка гипотезы

Если команда падает с пустым выводом + exit 1 и в ней есть Cyrillic + \(,
это скорее всего именно эта ловушка. Проверить:
  $PSVersionTable.PSVersion   # ожидается 7.6.x
  Упростить команду — убрать \(, повторить.
