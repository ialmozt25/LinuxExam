## ЧАСТЬ 1. ЧТО СТРОИМ

**Фраза:** фабрику, которая сама делает ИТ-продукты под управлением капитана.

**Цикл:** капитан ставит задачу → оркестратор собирает команду → агенты делают → дашборд показывает → капитан approve → коммит.

**Принцип «не на веру»:** любая находка подтверждается ссылкой на файл+строку или git-хеш. Без ссылки — гипотеза, в решения не идёт. Числа в плане, полученные из аудита (224 банка, 167 тестов, 2 ahead, spec 014/010) — **помечены «verify in F0»**: сверяются с репо на шаге F0.1.

## ЧАСТЬ 2. ДАШБОРД — 9 БЛОКОВ

1. **Паспорт** — фаза, шаг, прогресс, кто работает, токенов сожжено.
2. **План** — все 6 фаз со статусом и прогрессом.
3. **Сейчас делается** — карточки активных задач.
4. **Память** — 5 тетрадей: обновлено, записей, свежесть. Свежесть: 🟢 < 1 фазы, 🟡 1–2 фазы, 🔴 > 2 фаз.
5. **Тренды** — из `docs/memory/trends.jsonl`. Метрики: банк, закрыто задач/день, время в blocked, стоимость, автономность, rework rate.
6. **Пульс агентов** — из `.agent-teams/<id>/team.json`. **До F3 — «Нет агентов, MAS появится в F3»** (не молчит, не врёт).
7. **Решения** — append-only, дата + ссылка на источник.
8. **Тревоги** — расхождения документов, задачи > 1 дня, память > 2 фаз.
9. **Рассинхрон с origin** — ahead/behind. *(Иллюстрация макета, не реальные SHA.)*

**Обновление:** git pre-commit hook через `git config core.hooksPath .githooks` — одна команда, прописана в README F2. Если `last_sync` > 1 часа — жёлтая плашка. Если данных нет — «нет данных».
