# MAS Protocol — 5+1 ролей

## Назначение

После генерации батча вопросов (N штук) — обязательная проверка 5 ролями + ru_editor. Только 5/6+1 PASS (≥5 из 6 ролей PASS, ru_editor обязательно PASS) → коммит.

Протокол превращает L4.5 пайплайна v2.0 (HANDOFF §5.1) из декоративного шага в реальный гейт: каждый батч проходит 6 независимых точек зрения, а решение о приёмке принимается по формальному правилу, а не по общему впечатлению.

## Роли

1. **sysadmin_10y** — практик. Неверные команды, устаревшие ключи, малозначимые дистракторы.
2. **rhcsa_instructor** — методист. RHCSA EX200 objectives, обучающая ценность.
3. **ex200_examiner** — экзаменатор. Второй правильный ответ, двусмысленность стема, подсказки.
4. **beginner** — новичок. Понятен ли стем без гугла? Не угадывается ли ответ по форме опций?
5. **skeptic** — скептик. Что хейтер скажет? Где оспоримо?
6. **ru_editor** — редактор русского. Опечатки, грамматика, двусмысленности, формулировки.

## Формат голоса

`drafts/_votes/<batch_id>/<role>.json`, где `<batch_id>` — например `manage_software_2026-09-25`:

```
{
  "role": "sysadmin_10y",
  "batch_id": "manage_software_2026-09-25",
  "verdict": "PASS" | "NEEDS_FIX",
  "issues": [
    {"id": "ms_003", "severity": "blocker|minor", "comment": "..."}
  ]
}
```

`issues` пустой, если замечаний нет. `severity: "blocker"` означает, что затронутый id нельзя принимать ни при каком раскладе.

## Правило решения

- ≥5 из 6 PASS И ru_editor PASS → коммит.
- ≥2 NEEDS_FIX (или ru_editor NEEDS_FIX) → отклонить, вернуть генератору.
- 1 NEEDS_FIX (кроме ru_editor) → captain решает.
- Любой blocker → перегенерировать затронутый id.

## Последовательность вызова

Никогда параллельно (HANDOFF §12). Роли вызываются последовательно как субагенты или проходы одного агента.

Параллельный запуск ролей уже приводил к переполнению контекста (сессия 2026-09-24: 1 057 432 / 1 048 576 токенов). Порядок фиксирован: каждая роль завершается и записывает свой файл голоса до старта следующей.

## Связь с tools

После 5/6+1 PASS — прогнать:

```
node tools/qc.cjs
node tools/haladyna.cjs --batch <pending.json>
node tools/cosine.cjs <pending.json>
```

Все три — чистые. `qc.cjs` даёт exit 0 при Fails=0; `haladyna.cjs` считает 6 AUTO + 2 SEMI критерия и возвращает exit 0 только при auto=6/6 и semi=2/2 (SEMI_FAIL — сигнал человеку: критерии 7 и 8 требуют ревью, но не штрафуют автоматически); `cosine.cjs <pending.json>` проверяет кандидата против банка. MANUAL-критерии 9 и 10 (правдоподобность дистракторов, соответствие RHCSA) закрывают роли `sysadmin_10y` и `rhcsa_instructor` своими голосами.
