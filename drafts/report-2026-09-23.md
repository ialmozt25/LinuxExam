## Ложные следы и расхождения, которые я разрешил сам

1. **`useradd -a` — расхождение Factual/Examiner vs Skeptic.** Examiner утверждал, что `useradd -a` «меняет максимальный срок действия пароля (как `-f`)». Проверил лично: `useradd -a 90 lx_atest` → **`invalid option -- 'a'`**, пользователя нет, опции `-a` нет ни в man, ни в `--help`. Прав Skeptic. **Ответ A не меняется.**
2. **`useradd -n` — три расхождения подряд.** Мои первые два прогона дали «NOT_CREATED» (ложный отрицательный из-за сломанного cwd и съеденного `$?`). Чистая проверка через скрипт-файл: `useradd -n lx_n5` → **EXIT=0**, `lx_n5:x:4867:100::/home/lx_n5:/bin/bash`, `gid=100(users)`, каталог **отсутствует**; `useradd -N lx_n6` ведёт себя так же. Factual прав: `-n` — недокументированный алиас `--no-user-group`. Это усиливает риск `ug_002`, но **не создаёт второй верный ответ**.
3. **Ошибка метода на L5.** Я скопировал кандидатов в `drafts/`, из-за чего `loadDraftQuestions()` сравнил их сами с собой и дал `12/12 REJECT (cos=0.98, j=1)`. Файл удалён, прогон повторён — чистый результат.
4. **Убрана подтема lock/unlock.** Эмпирика показала, что `usermod -L` и `passwd -l` **обсервационно идентичны**, а разблокировка без заранее заданного пароля не работает ни через `usermod -U`, ни через `passwd -u`. Вопрос различался бы только текстом man, поэтому вместо него взяты проверяемо различимые подтемы.

## Правки класса A (4 вопроса)

Ревью подтвердило: 4 вопроса из 12 действительно допускали второй верный ответ,

### ug_010 — устаревающая абсолютная дата

| | Значение |
|---|---|
| Было | `chage -E 2026-12-31 alice` (+ те же даты в 3 дистракторах) |
| Стало | `chage -E 2099-12-31 alice` (+ те же даты в 3 дистракторах) |

**Почему:** после 31.12.2026 этот же пример начал бы задавать уже прошедшую дату, а `chage -E`
принимает прошедшие даты молча — учётная запись становилась бы мгновенно недействительной,
и «правильный» ответ превращался бы в ловушку. `explanation` переписан: теперь явно
оговорено, что `-E` принимает и просто число (дни от 1970-01-01), и покрыты все 4 ключа.

### ug_002 — `CREATE_HOME` давал второй верный ответ

| | Значение |
|---|---|
| Было | «Какой ключ useradd создаёт домашний каталог пользователя?» |
| Стало | «Какой ключ useradd **явно** создаёт домашний каталог **независимо от настроек системы**?» |

**Почему:** при `CREATE_HOME yes` в `/etc/login.defs` дистрактор `-d` **тоже** создаёт каталог
(проверено: `useradd -K CREATE_HOME=yes -d /home/lxz_h2 lxz_h2` → rc=0, каталог создан). Уточнение
«явно и независимо от настроек» делает `-m` единственным верным ответом, а `-d` — законно неверным.

**Проверка связи стема с опциями (обязательная):** все 4 опции сохранили смысл —
`-m` создаёт, `-n` создаёт без каталога, `-s` задаёт оболочку, `-d` задаёт путь (каталог только при
`CREATE_HOME`). 3 дистрактора не потеряли смысл → правка применена.

### ug_011 — `id -gn` совпадал с `id -nG` без доп. групп

| | Значение |
|---|---|
| Было | «Какая команда выведет только имена групп, в которые входит пользователь alice?» |
| Стало | «Пользователь alice входит в основную группу **и в дополнительные группы**. Какая команда выведет имена **всех** групп?» |

**Почему:** если у пользователя нет дополнительных групп, `id -gn alice` печатает ровно то же,
что `id -nG alice` → дистрактор C становился верным. Условие про дополнительные группы снимает
неоднозначность.

**Проверка связи стема с опциями:** `-nG` даёт имена всех групп; `-G` — числа; `-gn` — только
основную; `-g` — число основной. 4/4 осмысленны → правка применена.

### ug_007 — man неточен про `userdel -f`

Стем **не менялся** по указанию. Исправлен только `explanation`: добавлена явная фраза, что
man-страница `userdel` для ключа `-f` утверждает удаление домашнего каталога и почтового ящика,

## Селективность cosine 0.80 — уточнённая картина

Первоначальная оценка «порог ниже фона» **оказалась следствием другого pooling**.
`tools/cosine.cjs --self-check` измерил:

```
pairs: 861
max cosine: 0.7837  (fm_002~fm_003)
threshold: 0.8
calibration expected max: 0.7837  ->  MATCH
```

Причина расхождения: раннее число **0.8040** получено через `pipeline()`, чьё внутреннее
усреднение отличается от **явной mean-pooling по `attention_mask`**, реализованной в
`tools/cosine.cjs` (именно эта формула задана в спецификации). Пара-победитель совпадает,
значения различаются на 0.0203.

**Следствие:** порог **0.80 лежит на 0.0163 ВЫШЕ** измеренного максимума фона, то есть фильтр
фактически работоспособен; истинные перефразы в прошлом прогоне измерялись в диапазоне
0.855–0.963, что даёт полезную полосу разделения. Порог 0.80 **не изменялся** по указанию.

Числа зафиксированы в `tools/cosine-calibration.json` (поля `background`, `pooling_validation`,
`threshold_margin`); порог читается именно оттуда, а не из константы в коде.

## ⚠️ Аномалия: 12/12 без единого reject против 7/10 в пилоте

Прошлый пилот по `essential_tools` дал **7 из 10** (три отбраковки). Текущий прогон по
`users_groups` дал **12 из 12** без единого reject. Разница слишком велика, чтобы быть
случайной. Гипотезы:

1. **Мягкие L7/L8.** `L8` (чеклист 4/4) реализован как эвристика «требуемый токен опции
   встречается в explanation» — она почти всегда проходит. В прошлом пилоте работала
   содержательная проверка Haladyna, и `et_008`/`et_010` отбраковались именно по смыслу.
2. **Однородные критики.** Все три критика — субагенты одной модели с одинаковым контекстом;
   единогласие 3/3 достигается легко. В прошлом пилоте расхождения возникли из-за
   **эмпирической** проверки конкретных команд (`xargs -t 20`, `tr 'Z-A'`), а не из-за
   разнообразия ролей.
3. **Недостаточный duplicate-фильтр.** Порог cosine 0.80 не отклонил ни одной пары, Jaccard 0.9 —
   тоже; банк не пересекается с новым топиком, поэтому L5 просто не имел работы.

**Что ужесточить в следующей итерации:**
- заменить L8-эвристику на содержательный чеклист (покрытие всех опций, отсутствие клингов,
  правдоподобность каждого дистрактора с обоснованием);
- требовать от Skeptic **обязательный** проверяемый risk хотя бы по одному дистрактору, иначе
  вердикт не `pass` (сейчас отсутствие risk не наказывается);
- добавить L5-проверку «второй верный ответ при другом прочтении» как отдельный шаг с
  эмпирикой (именно она поймала `et_008`);
