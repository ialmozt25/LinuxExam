## 1. Главный принцип: Done = доказательство, а не галочка

Сегодняшний проектный DOD состоит из чекбоксов `- [ ]`, которые **ставит сам исполнитель
текстом**. Ничто не мешает поставить `[x]` без прогона. Внешняя практика (Spec Kit,
RESEARCH §4.1) требует обратного: критерий приёмки **исполняем** и проверяется.

**Фабричное правило:** каждый критерий имеет либо **команду с exit-кодом**, либо
**наблюдаемый артефакт**. Критерий без доказательства не считается выполненным, даже
если чекбокс стоит.

| Тип критерия | Чем доказывается | Пример |
|---|---|---|
| Гейт | команда + exit 0 + числа | `npm run qc` → `Fails 0, Warns 22`, exit 0 |
| Артефакт | путь + размер/строк | `.project/drafts/batch-5-preview.md`, 17 535 Б |
| Инвариант | сравнение до/после | целостность банка: `_order.json` 206 = сумма тем 206 |
| Решение | approve капитана в чате | ссылка на решение + дата |

## 3. Общий DOD (все типы задач)

Задача done, когда **все** пункты выполнены и доказаны:

| # | Требование | Доказательство | Обязательно |
|---|---|---|---|
| О1 | Есть спека `.project/specs/NNN-slug.md` (правило 1) | путь + `status` | да |
| О2 | Капитан дал approve на исполнение (правило 2) | решение в чате | да |
| О3 | Preview показан **до** коммита | путь к preview + числа | да, для типов `content`/`ui` |
| О4 | Инварианты И1–И6 выполнены | вывод проверок | да |
| О5 | Гейты типа задачи зелёные | команды + exit-коды | да |
| О6 | `npm run typecheck` exit 0 | вывод | да |
| О7 | `npm run test:run` exit 0 | число passed/total | да |
| О8 | Коммит атомарный, conventional | `git log -1 --format=%s` | да |
| О9 | `npm run sync` → коммит производных → `npm run sync:check` exit 0 | вывод гейта | да |
| О10 | Строка в `.project/log.md` (append-only, правило 5) | последняя строка файла | да |
| О11 | `status: done` + SHA в frontmatter спеки | содержимое спеки | да |
| О12 | Push — только при approve капитана (правило 4) | решение | да |
| О13 | Известные отклонения зафиксированы в спеке | раздел «Отклонения» | да |

### 3.1 Честная цена О9 — известный долг

О9 сегодня требует **трёх** действий (`sync` → коммит → `sync:check`) и добавляет
**+1 коммит на задачу** из-за ловушки `sync:check`: любой не-sync коммит двигает HEAD,
`state.head` отстаёт, гейт краснеет при корректных производных. За ночь 2026-09-27 это
стоило **5 лишних коммитов**. Дополнительно `npm run sync:check` **сам перезаписывает**
`.project/state.json` — «проверочная» команда имеет побочный эффект записи.

**Решение:** спека `009` (единый вход, честный exit-код). До её внедрения О9 остаётся
в силе как есть, но цена зафиксирована здесь, чтобы она не выглядела нормой.

## 4. DOD по типам задач

### 4.1 `content` — MCQ-вопрос

Совпадает с проектным DOD (`content`), плюс фабричные требования.

| # | Критерий | Доказательство | Состояние |
|---|---|---|---|
| C1 | 4 опции, ровно 1 верная | проверка по каждому id | **есть**: `positional-distribution.test.ts` + `qc` |
| C2 | ratio в пределах **класса** | `checkRatio(options,'chars')` → `verdict` не `fail` | **есть**: `tools/_lib/ratio.cjs` |
| C3 | explanation ≤ 3 строк | нет `\n`; длина в разумных границах | **есть**: `qc` (частично) |
| C4 | cos против **всего** банка ≤ 0.85 | `tools/cosine.cjs` | **есть** |
| C5 | cos внутри партии ≤ 0.85 | `--intra-batch` | **есть** |
| C6 | тема из канона (14) | `src/data/topics.ts` | **есть** |
| C7 | avoid-list соблюдён | ручная сверка | **слабо**: нет машинной проверки |
| C8 | независимая верификация QC | `writer_to_qc` + verdict | **есть** |
| C9 | `npm run qc` Fails 0 | вывод + числа | **есть** |
| C10 | `shuffle-bank:check` exit 0 | вывод | **есть** |
| C11 | preview + approve капитана | путь к preview | **есть** |

**Расхождения проектного DOD и кода (зафиксировано в смене 2026-09-27):**

- Проектный DOD пишет «ratio ≤ 1.5» **плоско**, а гейт берёт порог **по классу слов**:
  `sentences` 1.30 / `token` 2.00 / `mixed` 1.50. При этом ratio измеряется **в символах**.
  Следствие: вопрос с char-ratio 1.4118 формально проходил DOD, но валил `npm run qc`.
  Фабричный C2 сформулирован по **классу**, а не по плоским 1.5. Долг закрывает спека `007`.
- Проектный DOD не упоминает avoid-list как критерий, хотя он есть в спеках батчей.

**Замеренный baseline на банке 206** (использовать как эталон регрессии):
`Total 206 · Fails 0 · Warns 22` (absolute=2, length-hint=2, ratio=16, stopword=2);
`shuffle-bank:check` → `BANK 206 = 59/47/42/58`; `test:run` → 149/149.

**🔒 Freeze:** правило 6 закрывает контент-трек. Банк **206**, content-спеки не создаются
и не исполняются без разморозки. Этот блок DOD описывает, **чем** задача считается
выполненной, но не разрешает её начать.

### 4.4 `infra`

**Это самый слабый тип: отдельного DOD для него сегодня нет.** Есть только общий блок
«все типы» в проектном DOD (`build`, один коммит, строка в `log.md`). Инфраструктурные
задачи ночи (`009`, `010`) шли без формальных критериев.

| # | Критерий | Доказательство | Состояние |
|---|---|---|---|
| I1 | существует **откат** (rollback) | описание в спеке | **отсутствует** |
| I2 | поведение зафиксировано **до** изменения | baseline-файл | **отсутствует** → контракт `orchestrator_to_test` |
| I3 | изменение гейта воспроизводит baseline | повторный прогон даёт те же вердикты | **отсутствует** |
| I4 | гейт возвращает **честный** exit-код | exit ≠ 0 при красном состоянии | **нарушено**: `state:update` возвращает 0 при красных гейтах |
| I5 | нет скрытых побочных эффектов у «проверочных» команд | команда не пишет файлы | **нарушено**: `sync:check` пишет `state.json` |
| I6 | известные артефакты легаси не уезжают в коммит | `git status` по `docs/dashboard/` | **есть** как правило (DECISIONS п.7) |
| I7 | инварианты И1–И6 | вывод проверок | **есть** |

I1–I5 — это **и есть содержание Фазы 2**. Каждый пункт уже подтверждён находкой аудита
(`tools-audit-2026-09-27.md`: 16 дефектов, 2 high) или инцидентом смены.

## 5. Где именно капитан входит в DOD

| Тип | Точки входа капитана | Что он решает |
|---|---|---|
| `content` | approve на старт (О2), preview/approve артефакта (О3), partial approve | сколько вопросов идут в банк |
| `ui` | approve на старт, **preview-скриншот** (U2) | приемлем ли интерфейс визуально |
| `feature` | approve на старт, приёмка API-контракта (F2) | верна ли граница модуля |
| `infra` | approve на старт, approve изменения гейтов, **push** (О12) | можно ли менять правила проверки |

**Правило, которое нельзя размывать:** ни один тип не объявляется done, если
`npm run sync:check` ≠ 0 (правило 3). Ни один тип не идёт в прод без approve (правило 4).

Чтобы DOD применялся, а не пересказывался, спека в Фазе 2 получает ссылку:

```markdown
- Тип: `infra`

- Неприменимые (с обоснованием): I3 — изменение не касается вердиктов гейта

  - `npm run qc` → Total 206, Fails 0, Warns 22
  - `npm run shuffle-bank:check` → BANK 206 = 59/47/42/58
  - `npm run test:run` → 149/149
- Откат: `git revert <sha>` (изменение изолировано в одном файле)
```

Такой блок превращает DOD из политики в **проверяемый вход задачи**.
