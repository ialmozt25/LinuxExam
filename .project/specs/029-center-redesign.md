# Спека 029 — Center redesign (три уровня)

Источник фактов: `docs/C0-CENTER-AUDIT.md` (C0, коммит `0074d35`). План: `docs/C-PLAN.md`.
Реализация — фаза C2. Этот документ код не меняет.

## Цель

Перестроить `docs/index.html` (генерируется `renderCenter()` в `.project/sync.mjs`)
так, чтобы центр отвечал на вопрос «что сейчас происходит» за 5 секунд, а вся
справочная масса открывалась по требованию. Сохранить все факты: ничего не
удаляется без решения, зафиксированного в разделе «Зафиксированные решения».

## Проблема

- 18 секций + 1 `<details>` — плоский поток без уровней; ~879 строк разметки.
- Первый экран занят прогрессом банка из 14 полос тем.
- `log.md` показан дважды: «Журнал» (10 строк, полный текст) и «Решения»
  (5 строк, обрезка до 80 симв.) — пересечение 5 из 10.
- План показан двумя близнец-блоками (`plan-factory`, `plan-dev`), оба «✅».
- Завершённые инициативы (F0–F5, D0–D4) занимают больше места, чем активная работа.
- Жаргон в текстах: `commit pending`, `sync:check`, `exit 2`, `ORCH-RULES`,
  `[AUTHORIZE]`, SHA-хеши, ISO-таймстампы — 36 коротких SHA и 6 ISO-дат в видимом тексте.
- Данные продукта (`Прогресс банка`, `Продукты`) смешаны с состоянием фабрики.

## Структура (три уровня)

### Уровень 1 — Пульс (3–4 плитки, ответ за 5 секунд)

| плитка | содержание | источник |
|---|---|---|
| Состояние | 🟢 «Всё работает» / 🔴 «есть расхождение» + «обновлено N назад» | `inSync` (реальная проверка), `state.last_sync` |
| Банк | `224/300 · 74.7 % · +18 за сутки` | `state.goal.current_questions`, `target_questions`, `added_today` |
| Требует решения | число спек в статусе `preview` («0» → «—») | `readSpecs()`, `status === 'preview'` |
| Долги | «открытых тревог: 13» (18 записей − 5 `[closed]`) | `docs/memory/alerts.md` |

### Уровень 2 — Дела

- **Требует решения** — записи очереди (при непустой очереди) с целью и ссылкой на спеку.
- **Сейчас делается** — Doing + Next из `renderDoneDoingNext()`; Done сжимается до счётчика.
- **Тревоги** — сводка «открытых: N» + старейшая дата; полный список — в Справочнике.
- **Пульс агентов** — карточки команд с человеческими статусами («работает» / «ждёт одобрения» / «завершена»).
- **План** — один блок активного плана (C-PLAN); завершённые — одной строкой «закрыто: F0–F5, D0–D4».

### Уровень 3 — Справочник (`<details>`)

Коммиты, журнал (объединённый), спеки, тренды, память и тетради, политики,
роли и продукты, аудит-индекс, тетради, полный список тревог. По умолчанию свёрнут.

## Фиксы багов (в C2)

1. **wall-clock «свежий draft» → VOLATILE.** `DOING_DRAFT_WINDOW_MS` жил 2 часа
   (`sync.mjs:1125`), решение принималось по `Date.now()` (`:1453`), участок не
   обёрнут маркерами. Материализация draft-спеки переезжает из Doing в Next без
   правки источников → `sync:check` краснеет без реального дрейфа. Обернуть
   в VOLATILE, как `commitRows` и `notebookRows`; либо считать окно от данных.
2. **`roles.yaml:52` «банк 206» → 224.** Устаревшее число печатается в центре
   как факт (секция «Роли»); зеркало — `state.json:892`.
3. **`renderCenter` `inSync: true` → реальная проверка.** Сейчас функция всегда
   вызывается с `inSync: true` (`sync.mjs:1942`), поэтому сообщение «есть
   расхождение (запусти npm run sync)» недостижимо — мёртвая ветка.
4. **Остальные 4 бага — см. `docs/C0-CENTER-AUDIT.md`, раздел «G5. Найденные
   баги в sync.mjs»:** мёртвая константа `MEMORY_FACTORY_PATH` с несуществующим
   путём; мёртвая переменная `doingAll`; `added_today`/`avg_daily_7d` есть в
   источнике, но не выводятся в центре; команды со всеми выполненными задачами
   печатаются как `running`.

## Гуманизация текстов

- `commit pending` → «ещё не закоммичено»; `sync:check` → «проверка синхронизации»;
  `exit 2` → «не прошла»; `ORCH-RULES` → «правила оркестратора»; `[AUTHORIZE]` →
  «push разрешён»; `rule2-exception` → «исключение из правила 2».
- SHA-хеши (36 коротких + 1 полный) — из первого экрана убрать; в Справочнике
  оставить как `commit 9718583`.
- ISO-таймстампы (`2026-09-27T15:37:59.477Z`) → «обновлено 27.09, 15:37» либо
  «3 ч назад».
- `.mjs` / `state.json` / `log.md` в текстах → человеческие названия
  («генератор центра», «журнал работ»).
- Сырые тексты `log.md`/`alerts.md` не переписывать — их нормализует рендер:
  обрезка по границе предложения вместо 80 символов, фильтр `[closed …]`
  в сводке, ссылки `файл:строки` оставить только в Справочнике.

## Критерии приёмки (8 пунктов)

1. Первый экран — 3–4 плитки; на 1440×900 прокрутки нет.
2. Плитка «Банк» показывает число, процент и «+N за сутки» из `state.goal`.
3. Плитка «Требует решения» показывает число preview-спек (0 → «—»).
4. Плитка «Долги» = записи `alerts.md` без `[closed …]`.
5. `log.md` показывается ровно один раз (единый блок «Журнал»).
6. План — один блок; завершённые инициативы — одной строкой-сводкой.
7. Все справочные блоки — внутри `<details>`; удалённые факты либо там, либо сняты осознанно.
8. `npm run sync` → exit 0, `npm run sync:check` → exit 0, `check:episodic` → OK F0–F5 + D0–D4 (+ C0, C1 после подключения C-PLAN).

- `.project/state.json` — структура схемы (только `head`/производные поля, как обычно).
- `docs/C0-CENTER-AUDIT.md` — отчёт-артефакт C0.
- Данные банка (`src/data/questions/**`) и продуктовые метрики — не предмет C.

- `.project/log.md` и `docs/memory/alerts.md` — источники не переписываются,
  их подача нормализуется на рендере.

## Зафиксированные решения

1. DELETE — это про блок на первом экране; факт сохраняется в Справочнике
   (кроме `queue`, заменяемой плиткой, и `journal`, сливаемого с `decisions`).
2. Завершённые планы (F0–F5, D0–D4) сворачиваются в одну строку-сводку.
3. `alerts` уже в `<details>` (спека 028) — уровень 3 сохраняется, добавляется
   только сводка в Делах.
4. C-PLAN читается `sync.mjs` третьим источником шапки планов (C2), формат
   шапки — уже машинный.
5. Статус спеки — `draft`; перевод в `approved` и push — отдельный шаг C1-close.
