## Цель

Убрать хардкод ожидаемого размера банка из guard-теста
`src/data/questions/__tests__/positional-distribution.test.ts`, из-за которого
каждый новый батч вопросов требует ручной правки теста (`EXPECTED_QUESTIONS`
183 → 189 в M2.9 batch 4 — commit этой же сессии). После задачи тест должен
читать ожидаемое число вопросов из источника истины (`.project/state.json`
и/или `src/data/questions/_topics.json`), а не из константы в коде.

Возникло как tech debt M2.9 batch 4: spec 001 запрещал трогать
`src/data/questions/*`, но без правки константы гейт `npm run test:run` падал.
Капитан разрешил разовую правку 183 → 189 и потребовал отдельную спеку.

## Триггер запуска

**Сразу после approve batch 4, до batch 5.** Иначе следующий батч снова
потребует ручной правки константы.

## Критерии приёмки

- [ ] `EXPECTED_QUESTIONS` больше не хардкод: число берётся из источника
      (`.project/state.json` → `goal.current_questions` либо
      `src/data/questions/_topics.json` → `total`).
- [ ] Тест по-прежнему падает, если реальный размер банка разошёлся с
      источником (защита от регрессии не ослаблена).
- [ ] `EXPECTED_TOPICS = 14` — либо тоже выведено из источника, либо явно
      оставлено с обоснованием (число тем стабильно).
- [ ] Летопись-комментарий в тесте (строки про батчи `... to 14 / 189`)
      заменена на актуальную или удалена как дублирующая источник.
- [ ] `npm run test:run` exit 0 на банке 189.
- [ ] Проверено, что добавление вопроса в `_topics.json` без правки теста
      не требует правки теста (симуляция на копии).

## Что НЕ трогать

- Саму логику проверки позиционного распределения (порог `MAX_POSITION_SHARE`,
  смысл инварианта).
- `tools/shuffle-bank.mjs` — источник нормализации порядка опций.
- Контент вопросов банка.

## Превью

До/после `EXPECTED_QUESTIONS` в тесте + вывод `npm run test:run` на банке 189
с доказательством, что тест не сломан и не ослаблен (например, прогон на
намеренно испорченной копии банка).
