> **Состояние (2026-09-28, M6.0 Phase 4).** Спека переписана под **вариант 2**:
> smoke-тест читает **готовый** артефакт `docs/index.html` из репозитория
> (`fs.readFileSync` + `jsdom`) и **не импортирует** генератор `.project/sync.mjs`.
> Правки `sync.mjs` для исполнения спеки **не требуются** — генератор остаётся
> CLI-точкой входа и в тесте не участвует. Сам тест в Phase 4 **не создаётся**:
> исполнение целиком в **Phase 5**.

## Цель

Закрыть центр разработки (`docs/index.html`) smoke-тестами на структуру — **по готовому
артефакту**. Файл целиком генерируется `.project/sync.mjs` (`renderCenter()` + `esc()`) и
не покрыт ни одним тестом: сломанная таблица спек, потерянный класс чипа, пустая секция
«Очередь решений», обнулённый прогресс, статус вне схемы (`chip--blocked`) уезжают в
прод-центр молча. `sync:check` этого не ловит: он сравнивает производные с источником, но
не проверяет **смысл** разметки.

Известный прецедент класса ошибки: `renderCenter({ ... inSync: true })` захардкожен
(`sync.mjs:1280`), из-за чего индикатор синхронизации всегда зелёный
(`.project/audits/tools-audit-2026-09-27.md`, C.6). Такой дефект не виден ни `sync:check`,
ни глазами при беглом просмотре — ровно его и должен фиксировать новый smoke-тест.

## Что делать (вариант 2 — тест читает сгенерированный файл)

1. Создать один новый файл теста: **`docs/__tests__/center-smoke.test.mjs`**.
2. Прочитать артефакт как файл, а не как результат вызова генератора:

   ```js
   import fs from 'node:fs';
   import path from 'node:path';
   import { fileURLToPath } from 'node:url';
   import { JSDOM } from 'jsdom';

   const ROOT = path.resolve(path.dirname(fileURLToPath(import.meta.url)), '..', '..');
   const html = fs.readFileSync(path.join(ROOT, 'docs', 'index.html'), 'utf8');
   const dom = new JSDOM(html);
   const doc = dom.window.document;
   ```

3. Ожидаемые значения брать из источника, из которого артефакт собран, — `.project/state.json`
   (`fs.readFileSync` + `JSON.parse`, без импорта `sync.mjs`): `state.specs`,
   `state.topics`, `state.goal`, `state.log_tail`, `state.roles`, `state.products`,
   `state.audits`, `state.commits`.
4. Проверить утверждения из раздела «Что именно проверять».
5. Тест **read-only**: ни одного `writeFile`/`appendFile`/`rm`; `docs/index.html`
   не правится и не пересобирается; `.project/sync.mjs` **не импортируется** ни прямо,
   ни транзитивно.
6. Тест работает на **уже существующем в репозитории** артефакте: если `docs/index.html`
   отстал от `state.json` (`npm run sync:check` красный), это отдельный гейт, а не забота
   smoke-теста. Смоук проверяет то, что уже лежит в репозитории и уехало бы в прод.

**Чего в этой спеке нет:** требования импортировать `.project/sync.mjs`, рефакторинга
генератора, вариантов A/B и любых правок за пределами одного нового тестового файла.

## Что именно проверять (конкретные утверждения)

Смоук разбирает готовый `docs/index.html` и проверяет **структуру и согласованность с
источником**. Каждое утверждение — отдельный `it` с осмысленным именем на русском.

- [ ] **Артефакт на месте и разбирается.** `docs/index.html` существует, непустой, есть
      `<title>`; `new JSDOM(html)` не бросает исключений.
- [ ] **Секции центра.** В DOM присутствуют `#head`, `#progress`, `#ddn` (Done / Doing /
      Next), `#queue`, `#specs`, `#journal`, `#commits`, `#roles`, `#products`, `#memory`,
      `#audits`, `#policies` — все 12, каждая с непустым `textContent`.
- [ ] **Чипы статусов `#specs`.** Число строк таблицы спека === `state.specs.length`;
      каждая строка содержит ровно один `span.chip`; класс чипа матчит
      `chip--(preview|running|approved|draft|done|rejected)`, то есть **ни одного статуса
      вне схемы** (`chip--blocked` — регрессия, ловится этим утверждением); id строк
      уникальны и совпадают с `state.specs[].id`.
- [ ] **Прогресс `#progress`.** Текст `.progress__cur` ===
      `String(state.goal.current_questions)`, `.progress__tot` ===
      `` `/ ${state.goal.target_questions}` ``, ширина `.progress__fill`
      (`style="width:<percent>%"`) === числу `state.goal.progress_percent`,
      `.progress__pct` содержит процент и `осталось <target - current>`.
- [ ] **Темы (`.topic`).** Число элементов `.topic` === `state.topics.length`;
      `.topic__count` каждой строки матчит `` `${count} / ${target}` ``; тема с
      `count < target * 0.5` получает класс `topic--gap`, остальные — не получают.
- [ ] **Очередь решений `#queue`.** Если среди `state.specs` нет статуса `preview` — в
      `#queue` есть `p.empty` и ноль `.queue-item`; если есть — ровно столько
      `.queue-item`, сколько `preview`-спек, и в `.queue-item__meta` присутствует путь
      `.project/specs/<file>`.
- [ ] **Журнал `#journal`.** Число `li` === `state.log_tail.length`; при пустом
      `log_tail` — один `li.muted`; текст верхней строки совпадает с последней строкой
      `state.log_tail`.
- [ ] **Коммиты `#commits`.** Число строк `tbody tr` === `state.commits.length`;
      в каждой строке есть сокращённый SHA и subject; участок самоссылочности обёрнут
      маркерами `<!--volatile:start-->` / `<!--volatile:end-->` (иначе `sync:check`
      начнёт ловить дрейф от собственной истории).
- [ ] **Роли `#roles`.** Число карточек === `state.roles.length`; каждая содержит
      `title` и метку статуса (`active` / `planned`); роль с `trigger.check === null`
      помечена как ручной триггер, а не показана машинной.
- [ ] **Политики `#policies`.** Три карточки (`DOD`, `TOKENS`, `ORCH-RULES`), в каждой
      непустой `code`.
- [ ] **Шапка `#head`.** Содержит `HEAD` и `last_sync`; точка индикатора имеет класс
      `dot dot--ok`. **Известный дефект (фиксируется, не чинится):** `inSync: true`
      захардкожен (`sync.mjs:1280`), поэтому проверяется только наличие класса; после
      исправления утверждение расширяется до обеих веток (`dot--ok` / `dot--warn`).
- [ ] **Ноль побочных эффектов.** Тест не пишет в репозиторий: `git status --porcelain`
      до и после `npm run test:run` совпадает (проверяется в превью, а не внутри теста).

      exit 0.
- [ ] Строка в `.project/log.md`.

## Что НЕ трогать

- **`.project/sync.mjs`** — ни одной строки: генератор остаётся CLI-точкой входа;
  вариант 2 выбран именно потому, что правки генератора не нужны.
- **`docs/index.html`** — артефакт читается как входные данные; тест его не правит
  и не пересобирает (правка затирается следующим `sync`).
- Содержимое и вёрстку центра (разметка, CSS-токены, тексты) — задача про тесты,
  а не про редизайн.
- `.project/specs/**` (в т.ч. `README.md`), `.project/DOD.md`, `.project/state.json`,
  `.project/contracts/**` — не правятся.
- `src/**` (в первую очередь `src/data/**` — content freeze, правило 6) и `package.json`:
  новые зависимости не добавляются.
- Исключение `e2e/**` и `setupFiles` в `vitest.config.ts`: не переставлять, не удалять;
  `include` менять только если без этого тест не подхватывается (тогда — минимальным
  паттерном и с объяснением в отчёте). Ожидание: правки не нужны, путь попадает в
  дефолтный `include` (прецедент `docs/dashboard/__tests__/humanize.test.mjs`).
- `.github/workflows/deploy.yml` — CI-прогон тестов не добавляется.
