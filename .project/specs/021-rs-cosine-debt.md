## Цель

Снять «мягкий» cosine-долг темы `running_systems`: **три** пары, которые не нарушают
DOD-порог 0.85, но превышают жёсткую внутритематическую линию 0.80 из
`tools/cosine.cjs` (`INTRA_FAIL_THRESHOLD`), из-за чего
`node tools/cosine.cjs --intra-batch src/data/questions/running_systems.json` завершается
**exit 1**:

| пара | cosine | что общего у стемов |
|---|---|---|
| `rs_002` ~ `rs_007` | **0.8355** | юнит-файл и его правка (`daemon-reload`, переопределение) |
| `rs_004` ~ `rs_010` | **0.8261** | «журнал»/«служба» вокруг `httpd` |
| `rs_004` ~ `rs_005` | **0.8155** | журнал: выборка сообщений |

Это самый крупный из трёх долгов по числу пар: у `text_files` (spec 016) — две,
у `shell_scripts` (spec 019) — одна, здесь — **три**, что говорит не о локальной опечатке,
а о размытом словаре темы: пять вопросов группы `journalctl`/`systemctl` делят одни и те
же слова («служба», «юнит», «журнал», `httpd`).

Полоса 0.75–0.80 в теме пуста: следующая по близости пара — `rs_011`~`rs_012` (0.7622),
обе из батча 5C. То есть долг — ровно три пары, без «хвоста».

## Почему это долг, а не дефект гейта

- **DOD content не нарушен.** Порог DOD — cosine против **всего** банка ≤ **0.85**;
  0.8355 ниже него. `npm run qc` intra-косинус не прогоняет вовсе (`qc.cjs:16-20`:
  буфер 0.75–0.80 сознательно вынесен из быстрого гейта), поэтому `qc` остаётся зелёным
  (Total 224, Fails 0, Warns 22), а красной становится только отдельная intra-проверка.
- **Батч 5C ни при чём.** Все три пары состоят из вопросов `rs_001`..`rs_010`
  (единственное исключение — пара `rs_011`~`rs_012` из батча, и она ниже 0.80). Батч 5C
  **не добавил** ни одной пары выше 0.80 и ни одной — в полосе 0.75–0.80.
- **Whitelist.** В `tools/cosine-calibration.json` ровно одно исключение —
  `ug_005`~`ug_006`; ни одна из трёх пар в него не входит.

## Коммит (почему здесь нет `commit_format` / `commit_regex`)

README требует эти поля у `type=content`, **который добавляет вопросы** в банк, — иначе
`goal.added_today` / `avg_daily_7d` молча обнуляются. Эта спека вопросы не добавляет: она
разводит существующие пары, число вопросов темы не растёт. Поэтому subject её коммита
намеренно **не должен** матчить `/^feat\(bank\)/i` (образец формулировки — spec
`003-global-option-canonization`, тот же аргумент в spec 016 и 019). Если при исполнении
окажется, что вопрос всё-таки добавляется с ростом банка, поля `commit_format` и
`commit_regex` добавляются в frontmatter **в момент approve**, до коммита.
