### `shuffle-bank --apply` — единственная операция сверх append

`shuffle-bank:check` после интеграции дал **fail** (позиции верных ответов: 72/50/44/58
на банке 224), тогда как в батчах 5A/5B он проходил сразу. Причина в том, что все шесть
новых вопросов были написаны с верным ответом на первой позиции — распределение темы
перестало удовлетворять нормализатору. Выполнено ровно предписанное заданием:

```powershell
node tools/shuffle-bank.mjs --apply running_systems   # shuffled running_systems: 6 questions (salt 1)
npm run shuffle-bank:check                            # exit 0
```

Переставлены **только 6 новых вопросов** («files changed: 1, questions changed: 6») —
существующие `rs_001`..`rs_010` не тронуты, потому что уже стояли в каноническом порядке.
После операции верные ответы стоят на позициях 2, 4, 3, 3, 3, 2, распределение темы
`4/6/3/3`, банк `66/52/47/59`. Цикла «apply → check снова fail» не возникло (задание
требовало STOP в этом случае).

**Важно для чтения превью:** порядок опций в превью — тот, в котором вопросы были
написаны (верная опция первой). В банке порядок нормализован детерминированным
шаффлом (seed = хеш id), и **набор опций не изменился** — изменился только их порядок.
Это штатное поведение банка (правило `tools/shuffle-bank.mjs`), а не правка контента.

### Почему rework в этот раз не потребовался

В отличие от батча 5B, где блокер (`sh_012`, jaccard 1.00) всплыл **после** интеграции,
здесь QC на интегрированном банке прошёл сразу. Причина — оффлайн-пречек
`.project/drafts/qc-preview-check.mjs` (дословная копия правил `tools/qc.cjs`),
который до записи в `src/data/**` поймал:

1. `rs_011` = `systemctl edit` — **концептуальный дубль** `ds_006` при cosine всего 0.7308
   (порог такое не ловит; помогло чтение ближайшего соседа);
2. `rs_016` = `systemctl isolate` — дубль `rs_008`, cosine 0.8297 → REJECT;
3. `rs_016` = `systemctl list-dependencies` (вторая редакция) — **новая пара внутри батча**
   `rs_014`~`rs_016` = 0.8326, то есть батч сам добавлял близкую пару;
4. Haladyna SEMI 8 у `rs_013`/`rs_015` (в стеме не было пути или слова-команды) и ratio
   1.391 у `rs_015` выше warn-порога 1.35.

Независимое ревью отдельным агентом добавило пятое: в `rs_016` дистрактор `halt`
выполняет **тот же** цикл завершения работы и на реальном ACPI-железе тоже гасит питание —
`halt` становился вторым защитимым ответом. Правка: стем требует **гарантированного**
отключения питания, explanation формулирует различие по существу (вызов halt без гарантии
отключения питания). Все пять правок сделаны **до** любой записи в `src/data/**`.
