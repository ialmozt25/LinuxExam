## Цель

Описать ответственность роли **DevOps/ops** как **документ в базе знаний**, а не как
очередной DSH-пресет. В проекте уже есть два пресета (Writer, QC Auditor) и
устойчивый паттерн «роль = пресет», но у этого паттерна известное ограничение:
модель пресетом не задаётся — `readPresetMetadata()` читает только `name`,
`description`, `order`, а поле `model:` молча отбрасывается (DECISIONS
`2026-09-26 — QC Auditor: reference-копия, модель, YAML, pwsh-ловушка`).
Пресет также требует сброса/перезапуска DSH и живёт вне репозитория (reference-копия
в `docs/knowledge/dsh/presets/linuxexam-qc-auditor/`), то есть является дорогим
артефактом для роли, у которой пока нет ежедневной нагрузки. После задачи роль
DevOps определена, её триггеры и не-цели зафиксированы письменно, и решение
«документ или пресет» перестаёт быть вкусовым.

## Область роли (что должно быть в документе)

1. **Релиз и деплой.** Единственный пайплайн — `.github/workflows/deploy.yml`
   (GitHub Pages): триггер `push` в `main` + `workflow_dispatch`, шаги
   `actions/checkout@v4` → `actions/setup-node@v4` (Node 22, cache npm) → `npm ci` →
   `npm run build` с `VITE_BASE=/LinuxExam/` и `CI: true` →
   `actions/upload-pages-artifact@v3` (path `dist`) → `actions/deploy-pages@v4`.
   Прод — `https://ialmozt25.github.io/LinuxExam/` (правило 4 ORCH-RULES: без
   approve не трогать).
2. **Бэкап.** NAS-бэкап и restore drill — milestone **M4** (`.project/PLAN.md`,
   секция «M4: NAS-бэкап + Patterns Library»; `state.json.milestones` — M4
   `planned`). Роль владеет процедурой и регулярной проверкой восстановления.
3. **Гигиена зависимостей.** Item BACKLOG: «Dependabot: 52 уязвимости в default
   branch (1 critical, 23 high, 24 moderate, 4 low) — проверить и обновить
   зависимости». Роль владеет триажем и решением «обновлять / принять риск /
   зафиксировать в BACKLOG».
4. **Гейты перед релизом.** То, что DOD требует перед коммитом, и то, что
   `state:update` уже прогоняет (`qc`, `typecheck`, `test:run`,
   `shuffle-bank:check` — `tools/gen-state.mjs:419-455`); роль отвечает за то, чтобы
   релиз не уезжал на красном.
5. **Секреты и конфигурация окружений.** Чем управляем, где лежит, что нельзя
   коммитить (`node_modules`, `dist`, `.env` — AGENTS.md, «Запрещено»).
6. **Шум деплоя.** Item BACKLOG: `deploy.yml` без `paths-ignore` — doc-only push
   триггерит деплой Pages; исправление принадлежит этой роли.

## Где живёт документ

**`docs/knowledge/ops/devops-role.md`** — новый каталог `docs/knowledge/ops/`
рядом с существующим `docs/knowledge/dsh/`. Почему так:

- база знаний уже определена как место «как у нас принято»
  (`docs/knowledge/README.md`), и в ней уже есть подкаталоги по областям (`dsh/`);
- формат записи задан там же: **Проблема → Причина → Решение → Как избежать →
  Проверка** — документ роли пишется по этому шаблону;
- каталог `ops/` в `docs/knowledge/README.md` пока не упомянут — добавить строку
  в список «Что здесь», иначе документ будет сиротой.

**В этой задаче документ не создаётся** — эта спека `draft`, и создание документа
является предметом её выполнения.

## Триггеры «документ → пресет»

Документ остаётся документом, пока ни один триггер не сработал. Пресет создаётся
только при явном срабатывании одного из них (и только по approve капитана):

1. **Частота.** Роль вызывает DSH-агента ≥ 3 раза в неделю на протяжении ≥ 2 недель
   (считать по `.project/log.md` и `.project/drafts/`).
2. **Стандартный вход.** Появился повторяющийся вход (набор файлов + фиксированный
   набор команд), который каждый раз копипастится вручную.
3. **Ошибка из-за импровизации.** Зафиксирован инцидент, где агент без пресета
   сделал ops-действие иначе, чем описано в документе (пример: деплой без гейтов).
4. **Изоляция модели.** Возникла потребность в модели/фрейме, отличном от
   Orchestrator'а, и per-session `/model` перестал быть достаточным.

## Что НЕ трогать

- `src/**` — код приложения; задача чисто документационная.
- `.github/workflows/deploy.yml` — сама правка `paths-ignore` не входит в скоуп
  (отдельная задача по BACKLOG); здесь она только описана как владение роли.
- `docs/knowledge/dsh/**` и любые пресеты (в т.ч. reference-копия QC Auditor).
- `.project/DECISIONS.md`, `.project/log.md` (кроме одной append-строки в log),
  `.project/DOD.md`, `.project/ORCH-RULES.md`.
- `.project/state.json`, `.project/STATE.md`, `.project/SPEC.md`, `docs/index.html` —
  производные, обновляются `npm run sync`, а не руками.
