## Цель

Снять «мягкий» cosine-долг темы `text_files`: пары, которые не нарушают DOD-порог
0.85, но превышают **жёсткую внутритематическую линию 0.80** из `tools/cosine.cjs`
(`INTRA_FAIL_THRESHOLD`), из-за чего `node tools/cosine.cjs --intra-batch
src/data/questions/text_files.json` завершается **exit 1**:

| пара | cosine | статус |
|---|---|---|
| `tf_003` ~ `tf_007` | **0.8114** | цель этой спеки |
| `tf_003` ~ `tf_008` | **0.8004** | цель этой спеки |

После исполнения теме `text_files` разрешено считаться закрытой по теме: intra-прогон
даёт `pairs > 0.8: 0` и exit 0, при сохранении DOD-инварианта «cosine против всего
банка ≤ 0.85» у каждого вопроса.

## Замер (первая рука, не пересказ превью)

Команда и вывод на банке **212** (после батча 5A, HEAD `40191eb`, 2026-09-28):

```powershell
node tools/cosine.cjs --intra-batch src/data/questions/text_files.json
# intra-batch pairs: 120
# max cosine: 0.9020 (tf_001~tf_002)
# threshold: 0.8
# pairs > 0.8: 3
#   tf_001~tf_002: 0.9020
#   tf_003~tf_007: 0.8114
#   tf_003~tf_008: 0.8004
# pairs > 0.75: 10
# exit 1
```

Полоса 0.75–0.80 (WARN, не FAIL) — тот же кластер `cut`/`sort`/`uniq`, из которого
растут обе целевые пары: `tf_007~tf_008` 0.7984, `tf_005~tf_007` 0.7811,
`tf_003~tf_005` 0.7710, `tf_005~tf_006` 0.7689, `tf_005~tf_010` 0.7670,
`tf_002~tf_005` 0.7512, `tf_005~tf_008` 0.7511. Успех спеки — снять **FAIL-полосу
(> 0.80)**; сдвинуть WARN-полосу — желательно, но не критерий приёмки.

## Почему это долг, а не дефект гейта

- **DOD content не нарушен.** Порог DOD — cosine против **всего** банка ≤ **0.85**;
  0.8114 и 0.8004 ниже него. То есть интеграция батча 5A и `qc` зелёные законно,
  а эта спека — про ужесточённую добровольную линию, а не про красный гейт.
- **Пара `tf_001`~`tf_002` (0.9020) — не сюда.** Она выше DOD-порога 0.85 и является
  отдельным долгом; её судьбу решает spec `011-text-files-duplicate-repair`
  (`rejected` в рамках freeze). Походя её не чинить.
- **Батч 5A долга не создал.** Прогон `--intra-batch` по «6 кандидатов + `tf_001..tf_010`»
  дал ровно те же три пары выше 0.80, и все три — существующие, без единого кандидата
  (`.project/drafts/batch-5a-preview.md` §3). `tf_011..tf_016` в долге не участвуют.

## Коммит (почему здесь нет `commit_format` / `commit_regex`)

README требует эти поля у `type=content`, **который добавляет вопросы** в банк, —
иначе `goal.added_today` / `avg_daily_7d` молча обнуляются. Эта спека вопросы не
добавляет: она разводит существующие пары, число вопросов темы не растёт. Поэтому
subject её коммита намеренно **не должен** матчить `/^feat\(bank\)/i` (образец
формулировки — spec `003-global-option-canonization`). Если при исполнении окажется,
что вопрос всё-таки добавляется/заменяется с ростом банка, поля `commit_format` и
`commit_regex` добавляются в frontmatter **в момент approve**, до коммита.
