## Цель

Снять «мягкий» cosine-долг темы `shell_scripts`: пару, которая не нарушает DOD-порог
0.85, но превышает **жёсткую внутритематическую линию 0.80** из `tools/cosine.cjs`
(`INTRA_FAIL_THRESHOLD`), из-за чего
`node tools/cosine.cjs --intra-batch src/data/questions/shell_scripts.json` завершается
**exit 1**:

| пара | cosine | статус |
|---|---|---|
| `sh_004` ~ `sh_007` | **0.8311** | цель этой спеки |

После исполнения теме `shell_scripts` разрешено считаться закрытой по теме: intra-прогон
даёт `pairs > 0.8: 0` и exit 0 при сохранении DOD-инварианта «cosine против всего банка
≤ 0.85» у каждого вопроса.

## Замер (первая рука, не пересказ превью)

Команда и вывод на банке **218** (после батча 5B, 2026-09-28):

```powershell
node tools/cosine.cjs --intra-batch src/data/questions/shell_scripts.json --whitelist-aware
# intra-batch pairs: 120
# max cosine: 0.8311 (sh_004~sh_007)
# threshold: 0.8
# pairs > 0.8: 1
#   sh_004~sh_007: 0.8311
# pairs > 0.75: 1
# whitelisted exceptions: 1
# unwhitelisted pairs > 0.8: 1
# exit 1
```

Следующие по близости пары темы (для контекста кластера, все ниже линии 0.75):
`sh_008`~`sh_010` 0.7420, `sh_012`~`sh_014` 0.7403, `sh_007`~`sh_009` 0.7355,
`sh_013`~`sh_014` 0.7267, `sh_006`~`sh_010` 0.7176, `sh_004`~`sh_012` 0.7094. То есть
проблема **локальна**: одна пара, а не размытый кластер, — в отличие от темы
`text_files`, где вокруг `cut`/`sort`/`uniq` группировались семь пар (spec 016).

Содержательная причина близости `sh_004` и `sh_007`: оба стема говорят про файл
`list.txt` и «строки». `sh_004` — построчное чтение файла в цикле `while read`, `sh_007` —
подстановка `$(wc -l < list.txt)` в переменную. Механизмы разные, но словарь стема общий,
и эмбеддер это чувствует.

## Почему это долг, а не дефект гейта

- **DOD content не нарушен.** Порог DOD — cosine против **всего** банка ≤ **0.85**;
  0.8311 ниже него. `npm run qc` не прогоняет intra-косинус вовсе (см. комментарий в
  `qc.cjs:16-20`: буфер 0.75–0.80 сознательно вынесен из быстрого гейта), поэтому
  `qc` остаётся зелёным, а красной становится только отдельная intra-проверка.
- **Батч 5B ни при чём.** Обе половины пары — `sh_004` и `sh_007` из `sh_001`..`sh_010`;
  ни один из шести новых вопросов в пару не входит. Более того, батч 5B **не добавил** ни
  одной пары выше 0.75 — максимум с участием нового вопроса 0.7420.
- **Whitelist.** В `tools/cosine-calibration.json` ровно одно исключение —
  `ug_005`~`ug_006`; `sh_004`~`sh_007` в него не входит и исключением не считается.

## Коммит (почему здесь нет `commit_format` / `commit_regex`)

README требует эти поля у `type=content`, **который добавляет вопросы** в банк, — иначе
`goal.added_today` / `avg_daily_7d` молча обнуляются. Эта спека вопросы не добавляет: она
разводит существующую пару, число вопросов темы не растёт. Поэтому subject её коммита
намеренно **не должен** матчить `/^feat\(bank\)/i` (образец формулировки — spec
`003-global-option-canonization`). Если при исполнении окажется, что вопрос всё-таки
добавляется с ростом банка, поля `commit_format` и `commit_regex` добавляются в
frontmatter **в момент approve**, до коммита. Тот же аргумент, что в spec 016.
