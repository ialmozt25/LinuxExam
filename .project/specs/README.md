# .project/specs/ — спеки (очередь решений)

Правило 1 оркестратора: **без spec — нет задачи**. Одна задача = один файл
`NNN-slug.md` в этой папке.

Файлы пишутся **руками** (это входные данные), а всё производное —
`.project/SPEC.md`, таблица спеков и «Очередь решений» в `docs/index.html` —
генерируется из них через `npm run sync`.

## Шаблон

```markdown
---
id: 001
slug: dashboard-v13
status: preview
type: feature
created: 2026-09-27
updated: 2026-09-27
commit: null
---

## Цель

Одно-два предложения: какую проблему решает и что станет правдой после.

## Критерии приёмки

- [ ] Проверяемый пункт 1
- [ ] Проверяемый пункт 2

## Что НЕ трогать

- Файлы/области, которые задача не имеет права менять.

## Превью

Что капитан увидит перед approve (скриншот, URL, дамп вывода).
```

## Поля frontmatter

| Поле | Обязательно | Значения |
|---|---|---|
| `id` | да | `NNN` (номер по порядку) |
| `slug` | да | латиница, дефисы |
| `status` | да | `draft` · `preview` · `running` · `approved` · `done` · `rejected` |
| `type` | да | `content` · `ui` · `feature` · `docs` · `infra` |
| `created` | да | `YYYY-MM-DD` |
| `updated` | да | `YYYY-MM-DD` |
| `commit` | нет | короткий SHA после коммита, иначе `null` |

## Статусы

- `draft` — черновик, капитан ещё не смотрел.
- `preview` — **ждёт решения капитана**; попадает в «Очередь решений» на
  `docs/index.html`. Пока кнопок нет — approve/return делает капитан в чате.
- `running` — approve получен, работа идёт.
- `approved` — согласовано, но ещё не выполнено (например, ждёт окна).
- `done` — выполнено и закоммичено (`commit` заполнен).
- `rejected` — отклонено; причина — строкой в `.project/log.md`.

Порядок сортировки в индексе: `preview → running → approved → draft → done → rejected`.

## Проверка

```powershell
npm run sync          # перегенерировать индекс + центр
npm run sync:check    # гейт: exit 0 — производные совпадают с источником
```
