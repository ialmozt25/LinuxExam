## Цель

Убрать расхождение между DOD, инструментом и ожиданиями Writer'а в проверке
option ratio. Сейчас числитель и знаменатель считаются в **символах**, а класс
порогов выбирается по **числу слов**: Writer, считающий запас арифметикой по
«≤ 1.5» из `.project/DOD.md`, систематически его переоценивает, и зелёный по DOD
вопрос валит `npm run qc`. Это уже стоило одного цикла реворка (`fm_016`, batch 4,
DECISIONS 2026-09-27, п. 2). После задачи у гейта одна документированная единица
измерения, явная таблица порогов и воспроизводимый способ проверить кандидата тем
же кодом, что использует гейт.

## Наблюдаемое состояние (проверено чтением кода)

`tools/_lib/ratio.cjs:7-11`:

```js
const RULES = {
  sentences: { threshold: 1.3, warnFrom: 1.25 },
  token: { threshold: 2.0, warnFrom: 1.35 },
  mixed: { threshold: 1.5, warnFrom: 1.35 },
};
```

`tools/_lib/ratio.cjs:33-39` — класс по числу **слов**: все опции ≥ 4 слов →
`sentences`; все ≤ 3 слов → `token`; иначе `mixed`.
`tools/_lib/ratio.cjs:28-30` — длина: `unit === 'chars'` → `text.length`, иначе
число слов.
`tools/qc.cjs:13` — `const RATIO_UNIT = 'chars';`, `tools/qc.cjs:151` —
`checkRatio(q.options, RATIO_UNIT)`; вердикт в `tools/qc.cjs:152-156`.
`tools/haladyna.cjs:18,25,61` — второй потребитель, тоже `'chars'`.
Комментарий `tools/_lib/ratio.cjs:3` («по ЧИСЛУ СЛОВ (не символов)») описывает
дефолт библиотеки, а не фактическое поведение гейта.

**Не подтверждено:** историческое значение `fm_016` = 1.4118 (DECISIONS п. 2) —
исходная версия опций в репозитории отсутствует, замерить нечем
(`.project/audits/tools-audit-2026-09-27.md`, A.3). Проверяемое утверждение: при
классе `sentences` значение > 1.30 даёт `FAIL ... option ratio (sentences)`, то
есть формально проходит DOD (≤ 1.5) и валит гейт. Текущее `fm_016` = 1.20, `ok`.

**Baseline гейта (замерено `npm run qc` на банке 189):** `Total: 189 questions`,
`Fails: 0, Warns: 16`, exit 0; `WARN by category: absolute=1 ratio=13 stopword=2`;
категория `ratio-char` — 0 (легаси-проверка `tools/qc.cjs:143-149` с порогом 2.5
недостижима). Сводка печатает класс только в строках WARN/FAIL, агрегата по
классам нет (`tools/qc.cjs:200-201`). `tools/qc.cjs` не читает `process.argv`
вовсе — кандидатов нельзя ограничить областью проверки (BACKLOG: «добавить
поддержку `--batch <file>`»; DECISIONS п. 3).

## Критерии приёмки

- [ ] Единица измерения ровно одна и объявлена в одном месте: `RATIO_UNIT = 'chars'`
      экспортируется из `tools/_lib/ratio.cjs`; `tools/qc.cjs` и
      `tools/haladyna.cjs` используют экспорт, а не собственный литерал.
- [ ] В `tools/_lib/ratio.cjs` есть таблица порогов — единственный источник истины —
      с человекочитаемым описанием класса:

      | класс | условие (число слов) | FAIL при ratio > | WARN при ratio > | единица |
      |---|---|---|---|---|
      | `sentences` | все 4 опции ≥ 4 слов | 1.30 | 1.25 | символы |
      | `token` | все 4 опции ≤ 3 слов | 2.00 | 1.35 | символы |
      | `mixed` | иначе | 1.50 | 1.35 | символы |

- [ ] Пороги и условия классов в коде **не меняются** — задача про их документирование
      и предсказуемость, не про ужесточение/ослабление гейта.
- [ ] `.project/DOD.md` (раздел `content`, строка про ratio) ссылается на ту же единицу
      и ту же таблицу: сейчас там «ratio длин опций ≤ 1.5 (самая длинная / самая
      короткая)» без указания единицы и класса. После правки Writer может предсказать
      вердикт, не запуская гейт.
- [ ] Есть автотест нового пути: `tools/__tests__/ratio.test.cjs` (или `.mjs` с
      `createRequire`) на границах классов и порогов — `sentences` 1.30 → `ok`, 1.31 →
      `fail`; `token` 2.00 → `ok`, 2.01 → `fail`; `mixed` 1.50 → `ok`; поведение
      `warnFrom` (1.25 → `warn`, ровно 1.25 → `ok`); `computeRatio` с пустой опцией →
      `Infinity`. Тест подключается к существующему `npm run test:run` (Vitest 3).
- [ ] Прогон `npm run qc` на текущем банке неизменен или лучше: `Fails: 0`, exit 0,
      `Warns: 16` и `WARN by category: absolute=1 ratio=13 stopword=2` (число warning'ов
      не выросло). `Total` — фактическое значение из вывода.
- [ ] Один вердикт на вопрос: недостижимая легаси-проверка `ratio-char`
      (`tools/qc.cjs:143-149`) удалена либо сведена к порогам таблицы, чтобы одна
      метрика не получала двух диагнозов (audit, A.5, позиция 5).
- [ ] В выводе WARN/FAIL видно класс и единицу (уже есть) **и** в итоговой сводке есть
      агрегат по классам — чтобы по логу было понятно, какая таблица применилась.
- [ ] `npm run typecheck` exit 0; `npm run build` exit 0 (DOD, «Общее»).
- [ ] `npm run sync` → `git add` → один коммит → `npm run sync:check` exit 0.
- [ ] Строка в `.project/log.md` (append-only).

   ```powershell
   node -e "const {checkRatio,classifyOptions,RULES}=require('./tools/_lib/ratio.cjs');const o=['truncate -s 100 data.log','rm --force -- data.log','truncate -s 0 data.log','touch -c -m data.log'].map(t=>({text:t,correct:false}));console.log(classifyOptions(o),JSON.stringify(checkRatio(o,'chars')),JSON.stringify(RULES));"
   ```

   Ожидаемо: класс `sentences`, `ratio` 1.2, `verdict` `ok`, порог 1.3 — при том, что
   DOD обещает «≤ 1.5».

5. Явное указание, какие строки `.project/DOD.md` изменены.
