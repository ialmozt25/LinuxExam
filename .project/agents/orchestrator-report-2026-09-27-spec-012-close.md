## Находка (не отладка, для следующей сессии)

Volatile-обёртка `state.head` из spec 012 **не сделала `sync:check` самоподдерживающимся**:
после коммита гейт снова покраснел, и потребовалось ещё два цикла sync+commit.

Причина видна в диффах, без правки `sync.mjs`:

- `state.json` содержит **скользящий список последних коммитов** (`commits`).
  Любой новый коммит вытесняет из списка самый старый → `state.json` снова
  отличается от закоммиченного → `sync:check` = exit 2;
- вдобавок `state.head` при обновлении фиксирует **предыдущий** HEAD (значение
  вычисляется до коммита), поэтому после коммита головы расходятся
  (`state.head 7278078` ↔ `git HEAD ab501b1`, что сам гейт считает нормой — spec 009).

Итог: `ab501b1` — состояние, при котором `sync:check` = 0, но **любой следующий
коммит, двигающий `commits`, снова ломает гейт** до нового `sync` + коммита.
Это тот же класс незамкнутого цикла, который закрывала spec 012, и оставшийся
открытый корень — самоссылочный список коммитов. Решение принимать капитану
(в подходе "не трогать `sync.mjs`" тема остаётся открытой).
