# DOD.md — Definition of Done (ручная политика)

Задача не done, пока её тип не прошёл соответствующий блок ниже.
Правило 3 оркестратора: плюс к этому — зелёный `npm run sync:check`.

## content (MCQ-вопрос)

- [ ] 4 опции, ровно 1 верная.
- [ ] ratio длин опций (самая длинная / самая короткая) — в **символах** (`RATIO_UNIT = 'chars'`),
      порог зависит от класса вопроса по **числу слов**; таблица `RATIO_TABLE` в
      `tools/_lib/ratio.cjs` — единственный источник истины:
      `sentences` — все 4 опции ≥ 4 слов — FAIL при ratio > 1.30, WARN при ratio > 1.25 — символы;
      `token` — все 4 опции ≤ 3 слов — FAIL при ratio > 2.00, WARN при ratio > 1.35 — символы;
      `mixed` — иначе — FAIL при ratio > 1.50, WARN при ratio > 1.35 — символы.
      Формулировка «≤ 1.5» верна только для класса `mixed`: класс `sentences` валит гейт уже
      при ratio > 1.30. Проверить кандидата тем же кодом, что и гейт:
      `node tools/haladyna.cjs --batch <candidate.json>` (AUTO 2) или
      `checkRatio(options, RATIO_UNIT)` из `tools/_lib/ratio.cjs`.
- [ ] cosine против **всего** банка ≤ 0.85 (не только intra-batch).
- [ ] тема — из канона (`src/data/topics.ts`, 14 тем), не выдуманная.
- [ ] explanation ≤ 3 строк.
- [ ] гейты: `npm run qc` (Fails 0), `npm run shuffle-bank:check`.

## ui

- [ ] цвета/отступы/шрифты — токены из `TOKENS.md`, без хардкода значений.
- [ ] preview-скриншот показан капитану до коммита.
- [ ] jsdom-тест на структуру отрендеренного DOM.
- [ ] тема (dark/light) не сломана; текст интерфейса на русском.
- [ ] `npm run typecheck` и `npm run test:run` зелёные.

## feature

- [ ] выделен модуль (без копипаста логики в вызывающий код).
- [ ] API-контракт зафиксирован (сигнатуры, вход/выход, ошибки).
- [ ] feature flag (или явное обоснование, почему он не нужен).
- [ ] автотест на новый путь + отсутствие регрессий в существующих.
- [ ] миграция данных/состояния описана и выполнена, если меняется схема.

## Общее (все типы)

- [ ] `npm run build` — exit 0.
- [ ] один коммит, conventional-сообщение, без push без approve капитана.
- [ ] строка в `.project/log.md`.
