# TOKENS.md — дизайн-токены (ручная политика)

Формат токена, источник значений, кто меняет. Сами значения здесь не
выдумываются: канон — код приложения.

## Формат токена

```
--<область>-<роль>[-<вариант>]
```

- `--bg`, `--bg-elev` — фоны (базовый / приподнятый).
- `--fg`, `--fg-muted` — текст (основной / вторичный).
- `--accent`, `--ok`, `--warn`, `--fail` — сигнальные цвета.
- `--border` — границы; `--r-sm|md|lg` — радиусы; `--sp-N` — шаг 4px.

Правило: компонент не знает hex-значений, он ссылается на токен
(`var(--accent)`). Хардкод цвета/отступа в задаче = задача не done (см. DOD).

## Источник значений

- Канон приложения: `src/presentation/theme/tokens.css` (verbatim).
- Тема переключается атрибутом `data-theme` на `<html>` (`dark` / `light`).
- Копии токенов в артефактах (`docs/dashboard/dashboard.css`,
  `docs/index.html`) — **производные**: значения обязаны совпадать с каноном
  побайтово, иначе это дрейф.

## Кто меняет

- Добавить/изменить токен может только капитан через approve спеки типа `ui`.
- Оркестратор обязан сослаться на конкретную строку `tokens.css` в отчёте.
- Массовый ренейм токенов — отдельная задача (spec обязателен).
