## 2. Полный текст кандидатов

### `tf_011` — grep: подсчёт совпадений (medium)

**Вопрос:** В файле `/var/log/messages` нужно узнать, сколько строк содержат слово ERROR.
Какая команда выведет grep-подсчёт и больше ничего?

| | опция | верно |
|---|---|---|
| 1 | `grep -l ERROR /var/log/messages` | — |
| 2 | `grep -c ERROR /var/log/messages` | ✅ |
| 3 | `grep -n ERROR /var/log/messages` | — |
| 4 | `grep -w ERROR /var/log/messages` | — |

**Explanation:** Ключ `-c` заставляет grep напечатать только число строк, в которых
найдено совпадение, — ровно одно число на файл, без самих строк. Ключ `-l` печатает имя
файла, а не количество, причём только один раз. Ключ `-n` добавляет к каждой найденной
строке её номер, то есть выводит строки целиком. Ключ `-w` лишь ограничивает совпадение
целым словом и на счётчик не влияет.

### `tf_012` — grep: инвертирование совпадения (easy)

**Вопрос:** Нужно вывести строки файла `app.log`, в которых не встречается слово DEBUG.
Какая команда grep отберёт именно такие строки?

| | опция | верно |
|---|---|---|
| 1 | `grep -v DEBUG app.log` | ✅ |
| 2 | `grep -x DEBUG app.log` | — |
| 3 | `grep -q DEBUG app.log` | — |
| 4 | `grep -i DEBUG app.log` | — |

**Explanation:** Ключ `-v` меняет смысл отбора на обратный: печатаются строки, в которых
шаблон не найден, поэтому остаются только строки без DEBUG. Ключ `-x` требует совпадения
шаблона со всей строкой целиком, поэтому напечатает лишь строки, равные DEBUG. Ключ `-q`
отключает вывод вообще и сообщает результат только кодом возврата. Ключ `-i` расширяет
поиск на другой регистр, но инвертирования не выполняет.

### `tf_013` — grep: контекст до совпадения (medium)

**Вопрос:** Нужно увидеть строки со словом WARN в `trace.log` и по две строки перед
каждой из них. Какая команда grep это сделает?

| | опция | верно |
|---|---|---|
| 1 | `grep -A 2 WARN trace.log` | — |
| 2 | `grep -C 2 WARN trace.log` | — |
| 3 | `grep -B 2 WARN trace.log` | ✅ |
| 4 | `grep -n 2 WARN trace.log` | — |

**Explanation:** Ключ `-B 2` означает «before» — печатает две строки, расположенные до
каждого совпадения. Ключ `-A 2` печатает две строки после совпадения, то есть ровно
наоборот. Ключ `-C 2` объединяет оба направления и даёт по две строки с каждой стороны,
что шире требования. Ключ `-n` вообще не управляет контекстом: он лишь добавляет номера
строк к выводу, поэтому запись `-n 2` не даст строк перед совпадением.

### `tf_014` — wc: подсчёт строк (easy)

**Вопрос:** Сколько строк в файле `report.csv`? Какая команда wc выведет только это число?

| | опция | верно |
|---|---|---|
| 1 | `wc -c report.csv` | — |
| 2 | `wc -l report.csv` | ✅ |
| 3 | `wc -w report.csv` | — |
| 4 | `wc -m report.csv` | — |

**Explanation:** Ключ `-l` считает переводы строк, поэтому даёт число строк файла и
печатает только его. Ключ `-c` считает байты, ключ `-m` — символы, а эти числа для файла
с кириллицей различаются и к строкам отношения не имеют. Ключ `-w` считает слова. Без
ключей wc выводит сразу все свои значения, что требованию «только это число» не отвечает.

### `tf_015` — tee: запись и вывод одновременно (medium)

**Вопрос:** Скрипт печатает ход работы в stdout. Нужно и видеть вывод на экране, и
дописывать его в конец файла `run.log`, не затирая прошлые записи. Какая команда с tee
это сделает?

| | опция | верно |
|---|---|---|
| 1 | `script | tee run.log` | — |
| 2 | `script | tee -a run.log` | ✅ |
| 3 | `script | tee -i run.log` | — |
| 4 | `script > tee run.log` | — |

**Explanation:** tee дублирует поток: отдаёт его на экран и записывает в файл, а ключ `-a`
открывает файл в режиме добавления, поэтому прошлые записи сохраняются. Без `-a` файл
перезаписывается с начала. Ключ `-i` отключает обработку сигналов прерывания и к режиму
записи отношения не имеет. Запись `script > tee run.log` перенаправляет вывод в файл с
именем `tee`, а не передаёт его через tee, поэтому `run.log` остаётся нетронутым.

### `tf_016` — head/tail: срезы по знаку (medium)

**Вопрос:** Нужно вывести содержимое `data.csv` начиная с 50-й строки и до конца файла,
пропустив первые 49 строк. Какая команда tail или head это сделает?

| | опция | верно |
|---|---|---|
| 1 | `tail -n -50 data.csv` | — |
| 2 | `head -n 50 data.csv` | — |
| 3 | `tail -n +50 data.csv` | ✅ |
| 4 | `head -n -50 data.csv` | — |

**Explanation:** У tail знак «плюс» перед числом меняет отсчёт: запись `+50` означает
«начиная с 50-й строки до конца файла», поэтому первые 49 строк пропускаются. Запись `-50`
без плюса означает последние 50 строк — это другой срез. Команда `head -n 50` выводит
первые 50 строк, то есть выполняет обратную задачу. Команда `head -n -50` отбрасывает
последние 50 строк и выводит всё, что было до них.

## 3. Почему выбраны эти subtopic'ы и как они не дублируют `tf_001`..`tf_010`

Занятые subtopic'ы: `sed` подстановка (`tf_001`, `tf_002`), `sed` диапазоны (`tf_003`),
`awk` поля (`tf_004`), `cut` поля/диапазоны (`tf_005`, `tf_006`), `sort -u`/`uniq`
(`tf_007`, `tf_008`), `tr` регистр (`tf_009`), `tail -n` (`tf_010`).

Взяты **новые инструменты и новые режимы**, ни один из занятых subtopic'ов не повторяется:

- `grep` — три разных режима: счётчик `-c`, инверсия `-v`, контекст `-B` (в банке grep
  в `text_files` не было вовсе);
- `wc -l` (в банке `wc` был только упомянут в описании темы, вопросов не было);
- `tee -a` (новый инструмент);
- `tail -n +N` — знаковый режим, отличный от `tail -n N` из `tf_010`.

**Независимое подтверждение отсутствия дублей внутри темы.** Прогон
`cosine --intra-batch` по объединению «6 кандидатов + существующие `tf_001`..`tf_010`»
(120 пар) даёт 3 пары выше 0.80 — и **все три существующие, без единого кандидата**:

| пара | cos | в батче 5A? |
|---|---|---|
| `tf_001`~`tf_002` | 0.9020 | нет — известный долг (spec 011 `rejected`) |
| `tf_003`~`tf_007` | 0.8114 | нет — существующая пара |
| `tf_003`~`tf_008` | 0.8004 | нет — существующая пара |

То есть батч **не добавляет** новых близких пар, а пара `tf_003`~`tf_007`/`tf_003`~`tf_008`
(0.8114/0.8004, выше мягкого 0.80) — находка этого прогона; в аудите 2026-09-27 она не
числилась. Это долг существующего банка, не батча 5A: править походя нельзя (freeze снят,
но spec 011 `rejected` остаётся решением капитана).

## 5. Риски и места, где нужен человеческий взгляд

1. **Проверка только по документации.** Команды батча написаны и выверены по знанию
   GNU coreutils/grep, **без исполнения на Rocky 9** (среда DSH — Windows/PowerShell).
   Все опции (`grep -c/-v/-B/-n`, `wc -l`, `tee -a/-i`, `tail -n +N`, `head -n -50`)
   стандартные и переносимые, но это утверждение, а не замер.
2. **`head -n -50`** — GNU-расширение (в BSD/macOS `-n -50` не поддержан). Дистрактор
   корректен по смыслу для целевой платформы (Rocky Linux 9), но на другой платформе
   объяснение звучало бы иначе.
3. **`tee -i`** — редко используемый ключ; как дистрактор он правдоподобен, но требует
   от читателя больше знания, чем остальные. Если капитан считает его «слишком тёмным» —
   заменю на более простой вариант (`script | tee run.log` уже стоит первым).
4. **Haladyna MANUAL 9, 10** (соответствие цели экзамена, отсутствие «trick question»)
   автоматикой не проверяются: это субъективные критерии, их закрывает проверяющий.
