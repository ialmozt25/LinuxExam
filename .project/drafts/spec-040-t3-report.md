## 3. Принятые решения по неоднозначностям спеки

1. **Критерий приёмки 5 (ровно 5 заголовков `### Шаг `) против 8 пунктов
   Компонента B.** Согласовано условием задачи t3: 5 **логических** шагов
   покрывают все 8 пунктов, а в файле есть явная таблица маппинга
   (строка 54–80, §2 отчёта). Пункты 2, 4, 7 вынесены в STOP-точки A, B, C;
   пункт 8 — терминальная передача капитану; пункты 1, 3, 5, 6 — рабочие шаги.
2. **Порядок пунктов 3 и 4 спеки.** Буквально пункт 3 создаёт MAS-команду, а
   пункт 4 требует approve её плана — то есть approve пришёл бы уже после
   dispatch. Разрешено так: фазы 1–4 скилла `spec-to-team` (чтение спеки,
   roster, декомпозиция, валидация DAG) выполняются **до** STOP B, а
   `agent_teams_create` — только **после** явного approve. Инвариант пункта 4
   («approve до старта исполнения») соблюдён, скилл `spec-to-team` не изменён.
3. **Пункт 8 «Капитан → git push» не является шагом агента.** В таблице
   маппинга он привязан к Шагу 5 с пометкой «агентом не исполняется»;
   в тексте шага и в «Что не делать» зафиксировано: push — только капитан,
   отдельная per-command авторизация (правила 10/11), агент не пушит ни после
   approve, ни по таймауту.
4. **Таймаут STOP-точки.** Взят из Edge Cases спеки — 30 мин; добавлено
   уточнение «молчание не является согласием»: по истечении — отчёт и
   остановка без продолжения цепочки (для всех трёх STOP-точек).
5. **`npm run spec:enrich` — контракт с задачей t4.** Скрипт и npm-строка
   `spec:enrich` появляются в t4 spec 040; скилл на них ссылается, а отсутствие
   CLI (`npm` missing script) описано как STOP с диагностикой — цепочка не
   продолжается без отчёта enrich.
6. **Вердикт «clean» (0 hard-fail + 0 high-finding).** По Edge Cases спеки это
   STOP, а не пропуск: Шаг 1 завершается штатно, но продолжение — только после
   решения капитана на STOP-точке A (правки enrich могут быть не нужны).
7. **Параллельный запуск subagent'ов и работа за членов команды** запрещены
   (перенесено из раздела «Что не делать» скилла `spec-to-team`): оркестратор
   только наблюдает и координирует, файлы правят члены команды.
8. **`--dry-run` в Шаге 1 и Шаге 5** оставлен опциональным предусловием
   (критерии приёмки 2 спеки): в цепочке он показывается, но не обязателен —
   обязательным для продолжения является `exit 0` и отчёт со score delta.
