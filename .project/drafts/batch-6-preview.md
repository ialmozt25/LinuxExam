## Вопросы

### `msw_009` — dnf repoquery -l: список файлов пакета из репозитория

- **topic:** `manage_software` · **difficulty:** medium · **objective_domain:** `6`
- **question:** Пакет bash-completion в системе ещё не установлен, но нужно заранее посмотреть, какие файлы он установит. Список нужно взять из метаданных репозитория. Какая команда это сделает?

  - **A.** `dnf repoquery bash-completion`
  - **B.** `dnf repoquery -l bash-completion` ← **верный**
  - **C.** `dnf list bash-completion`
  - **D.** `dnf info bash-completion`

- **correct:** B
- **explanation:** Опция -l у команды repoquery выводит список файлов, которые пакет установит, а сведения берутся из метаданных репозитория, поэтому пакет не обязан быть установленным. Команда repoquery без опции -l показывает только сведения о пакете, а команда list ограничивается именем пакета и номером версии. Команда info печатает описание и размер пакета, но списка файлов не даёт ни один вариант, кроме первого.
- **Верификация:** dnf command reference (официальная документация); live-прогон невозможен — dnf в WSL нет.

### `msw_010` — rpm -V: проверка целостности файлов пакета

- **topic:** `manage_software` · **difficulty:** medium · **objective_domain:** `6`
- **question:** После сбоя при обновлении служба не запускается, и есть подозрение, что файлы установленного пакета bash изменены или повреждены. Нужно сравнить файлы на диске с контрольными суммами и правами из базы rpm. Какая команда это сделает?

  - **A.** `rpm -V bash` ← **верный**
  - **B.** `rpm -qi bash`
  - **C.** `rpm -qR bash`
  - **D.** `dnf info bash`

- **correct:** A
- **explanation:** Ключ -V сравнивает установленные файлы с метаданными пакета в базе rpm и печатает только расхождения по размеру, контрольной сумме, правам, владельцу и группе. При опциях -qi и -qR в режиме запроса проверка не запускается: первая печатает описание пакета, вторая перечисляет его зависимости. Команда dnf info тоже только показывает метаданные пакета из репозитория и целостность файлов на диске не проверяет.
- **Верификация:** man7.org `rpm.8` — формулировка `-V` совпадает дословно; live-прогон невозможен.

### `msw_011` — rpm -ivh: установка локального rpm-файла

- **topic:** `manage_software` · **difficulty:** easy · **objective_domain:** `6`
- **question:** Интернета нет, репозитории не подключены, но в текущем каталоге лежит файл htop-3.2.2-1.el9.x86_64.rpm, и его нужно установить. Какая команда установит этот пакет из файла?

  - **A.** `rpm -ql htop-3.2.2-1.el9.x86_64.rpm`
  - **B.** `rpm -qa htop-3.2.2-1.el9.x86_64.rpm`
  - **C.** `rpm -ivh htop-3.2.2-1.el9.x86_64.rpm` ← **верный**
  - **D.** `dnf install htop-3.2.2-1.el9.x86_64.rpm`

- **correct:** C
- **explanation:** Установку файла пакета выполняет ключ -i, а -v и -h добавляют подробный вывод и индикатор хода установки. Ключ -ql только перечисляет файлы, входящие в пакет, а -qa перечисляет установленные пакеты системы — обе команды ничего не устанавливают. Команда dnf install умеет ставить локальный файл, но перед этим обращается к метаданным репозиториев, а они не подключены, поэтому команда завершится ошибкой.
- **Верификация:** man7.org `rpm.8` (`-i`, `-U`) + dnf command reference (`dnf install <local.rpm>`); live-прогон невозможен.

### `msw_012` — dnf autoremove: удаление осиротевших зависимостей

- **topic:** `manage_software` · **difficulty:** medium · **objective_domain:** `6`
- **question:** Пакет htop удалили, но библиотеки, которые установились вместе с ним как зависимости, остались на диске, хотя больше никому не нужны. Нужно удалить именно эти осиротевшие пакеты. Какая команда это сделает?

  - **A.** `dnf clean all`
  - **B.** `dnf remove htop`
  - **C.** `dnf upgrade htop`
  - **D.** `dnf autoremove` ← **верный**

- **correct:** D
- **explanation:** Команда autoremove удаляет пакеты, которые были установлены как зависимости и больше не требуются ни одному пакету, выбранному пользователем. Команда remove удаляет только явно названные пакеты, а htop уже удалён, поэтому ничего не изменится. Команда clean all чистит лишь кэш скачанных файлов и метаданных, а upgrade, наоборот, ставит более новые версии пакетов.
- **Верификация:** dnf command reference — формулировка `autoremove` совпадает дословно; live-прогон невозможен.

### `msw_013` — dnf group install: установка группы пакетов

- **topic:** `manage_software` · **difficulty:** medium · **objective_domain:** `6`
- **question:** Нужно одной командой установить группу Development Tools вместе со всеми пакетами, которые в неё входят. Какая команда это сделает?

  - **A.** `dnf repoquery "Development Tools"`
  - **B.** `dnf group list "Development Tools"`
  - **C.** `dnf group install "Development Tools"` ← **верный**
  - **D.** `dnf group info "Development Tools"`

- **correct:** C
- **explanation:** Подкоманда group install помечает группу установленной и ставит все её обязательные и выбираемые по умолчанию пакеты. Подкоманды group list и group info только показывают группы и их состав, ничего не устанавливая. Команда repoquery выводит сведения о пакетах по запросу, но групп не раскрывает и установку не выполняет.
- **Верификация:** dnf command reference (Group Command) + метаданные comps Rocky 9 AppStream: id группы — `development`, отображаемое имя — «Development Tools».

### `msw_014` — rpm -qp --scripts: сценарии установки из файла пакета

- **topic:** `manage_software` · **difficulty:** medium · **objective_domain:** `6`
- **question:** Перед установкой скачанного файла myapp-2.1.0-1.el9.x86_64.rpm нужно посмотреть, какие сценарии установки и удаления он выполняет. Какая команда покажет эти сценарии из файла пакета?

  - **A.** `rpm -qlp myapp-2.1.0-1.el9.x86_64.rpm`
  - **B.** `rpm -qip myapp-2.1.0-1.el9.x86_64.rpm`
  - **C.** `rpm -qp --scripts myapp-2.1.0-1.el9.x86_64.rpm` ← **верный**
  - **D.** `rpm -qp -R myapp-2.1.0-1.el9.x86_64.rpm`

- **correct:** C
- **explanation:** Опция --scripts выводит сценарии пакета, которые выполняются при его установке и удалении, а ключ -p направляет запрос в файл пакета, а не в базу установленных. Ключ -l с той же опцией -p печатает лишь список файлов пакета, а ключ -i показывает его описание и версию. Ключ -R перечисляет зависимости пакета и сценарии не показывает.
- **Верификация:** man7.org `rpm.8` (`--scripts`, пример с `rpm -qp --scripts … .rpm`); live-прогон невозможен.
