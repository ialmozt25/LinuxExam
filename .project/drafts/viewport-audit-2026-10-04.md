# Viewport audit — 2026-10-04 (spec 075)

Аудит вёрстки по сетке из **5 viewport'ов × 11 экранов = 55 комбинаций** и
проверка TMA-режима моком. **Только детекция:** ни одна UI-проблема в этой спеке
не исправлялась (это прямо исключено заданием).

## Источники и метод

| Источник | Что даёт |
|---|---|
| `e2e/layout-smoke.spec.ts` | 55 тестов: `#root` overflow, 9 CTA во вьюпорте (`{ratio: 1}`), тач-цель ≥ 44 px, обрезанный текст (`h1`,`h2`,`label`), элементы за границами |
| `.project/drafts/layout-probe-075.json` | сырые замеры всех 55 комбинаций: координаты CTA, размеры тач-целей, элементы ниже сгиба, нарушения, реестр известных |
| `e2e/tma-mode.spec.ts` | 4 теста TMA-режима на 390×720 (мок канала SDK + ответы клиента) |
| spec 074 | база для классификации «известное/новое»: `.project/drafts/design-audit-2026-10-04.md`, `layout-probe-2026-10-04.json` |

**Viewport'ы:** `mobile-min` 360×640 (Telegram-минимум), `mobile-se` 375×667,
`mobile-tma` 390×720 (TMA bottom sheet), `mobile-px` 412×915, `desktop` 1440×900.

**Ограничение документации.** Жёсткого минимума размера Mini App в документации
платформы нет: описаны свойства viewport (`width`/`height`/`stability`/`expansion`/
`safe area`) и то, что приложение открывается в `BottomSheet` на минимальной
высоте ([docs.telegram-mini-apps.com/platform/viewport](https://docs.telegram-mini-apps.com/platform/viewport)).
360×640 — эмпирический нижний край мобильного WebView, а не документированное
требование; в отчёте это зафиксировано, чтобы цифру не приняли за норму платформы.

**Интерпретация «нет элементов за границами».** Буквальное «`top ≥ 0 && bottom ≤
innerHeight` для всех `[data-testid]`» на прокручиваемом экране (`#root` —
единственный скролл-контейнер) помечает почти весь дашборд: за сгибом легально
лежат 13–32 узла. Нарушением считаются горизонтальный выход и `top < 0`; элементы
ниже сгиба пишутся в JSON (`belowFoldTotal`) и проверяются адресно по списку CTA.

## 2. Элементы за границами: шапка Paywall уходит ВЫШЕ вьюпорта

| Размер | `header-home` («На главную») | `app-header-center` («LinuxExam») |
|---|---|---|
| 360×640 | **top = −187.8** | top = −174.8 |
| 375×667 | **top = −159.3** | top = −146.3 |
| 390×720 | **top = −132.8** | top = −119.8 |
| 412×915 | **top = −25.5** | top = −12.5 |
| 1440×900 | внутри вьюпорта | внутри вьюпорта |

- Обе кнопки шапки — **части `Paywall.tsx`**: `AppHeader` рендерится внутри того
  же контейнера, что и контент — `src/presentation/screens/Paywall.tsx:102`
  (`<ScreenContainer data-testid="paywall" style={{ justifyContent: 'center' }}>`).
- Механика проверена отдельной пробой: **ни один элемент на экране не прокручен**
  (`#root.scrollTop = 0`, `window.scrollY = 0`, у `[data-testid="paywall"]` нет
  своего скролла), при этом контейнер `paywall` занимает ровно `0…720`, а его
  первый ребёнок (шапка) лежит по отрицательному `top`. Это классическое
  поведение `justify-content: center` при переполнении: содержимое выходит за
  верхнюю кромку, и добраться до него прокруткой нельзя (скроллер видит только
  свой бокс). Чем меньше экран, тем глубже провал: 412×915 → −25.5, 360×640 →
  −187.8.
- `elementFromPoint(195, 20)` на paywall отдаёт абзац контента («Вы ответили на 5
  вопросов…»), то есть шапка не просто за краем — её место занято текстом.
- Практический эффект: пользователь попадает на пейволл **без видимой навигации**
  (кнопка «На главную» недостижима); выйти можно кнопкой «Позже»
  (`paywall-later`) или системным «назад». **Новое в 075**, в 074 не измерялось.

## 4. Обрезанный текст

Ни одного нарушения: `h1`, `h2`, `label` на всех 55 состояниях имеют

## 5. TMA-режим (mock)

**4 теста: 4 passed** (`e2e/tma-mode.spec.ts`, 390×720).

| # | Что проверяет | Статус |
|---|---|---|
| 1 | `isTMA() === true` (DEV-бейдж `TG: Test`), в консоли нет «Not in Telegram», в канал ушли `iframe_ready` + `web_app_request_viewport` | **passed** |
| 2 | quiz → ответ → в канал ушёл `web_app_setup_main_button` с `text: «Следующий вопрос»`, `is_visible: true`, `is_active: false` → после ответа `is_active: true`; in-app `next-button` в DOM отсутствует | **passed** |
| 3 | фолбэк: `isTMA()` true, но SDK не поднялся (MainButton не смонтирована) → in-app футер виден, `next-button` целиком во вьюпорте, событий настройки в канале нет | **passed** |
| 4 | `visualViewport.height === 720`, `innerHeight === 720`, ширина 390 | **passed** |

**RECON: почему в spec 072 TMA-ветку поднять не удалось (6 вариантов мока) — и что
оказалось причиной.** Мок состоит из трёх слоёв, без любого из них ветка не
поднимается:

1. **Гейт инициализации** — `src/main.tsx:108-119` грузит SDK только если
   `window.Telegram.WebApp != null` (или `VITE_MOCK_TELEGRAM=1`). Варианты 072 с
   одними launch-параметрами гейт не открывали: `initTelegramSDK()` не вызывался.
2. **Хранилище launch-параметров** — SDK читает их через
   `@telegram-apps/toolkit` `getStorageValue`, а тот работает с
   `sessionStorage['tapps/' + key]` (`function g(o){return "tapps/"+o}`) и хранит
   значение как JSON. Запись в `localStorage['launchParams']` (как пробовали в 072)
   SDK **не видит вообще** — отсюда «Not in Telegram» при «правильных» параметрах.
   Строка собирается штатными сериализаторами SDK: ручная не проходит парсер
   (`signature` в init data и `tgWebAppThemeParams` обязательны).
3. **Ответы клиента** — SDK слушает `window` `message` с `source === window.parent`
   и `data = { eventType, eventData }`. Без ответов на `web_app_request_theme` /
   `web_app_request_viewport` промисы `themeParams.mount()` не резолвятся:
   `isTMA()` уже `true`, а `#root` остаётся пустым (измерено: `rootChildren = 0`).

Ограничение, которое **не** снимается моком: недоступность MainButton при живом
TMA-режиме версией/платформой WebView не воспроизводится — проверены 6 комбинаций
(`5.0`/`6.0` × `android`/`web`/`tdesktop`/`macos`), `web_app_setup_main_button`
уходит в канал во всех. Тест 3 поэтому воспроизводит состояние «`isTMA()` true,
но SDK не поднялся» (закрытый гейт), а не «старый клиент Telegram». Реальный
клиент мок не заменяет — ручная проверка на устройстве остаётся единственной
гарантией.

**Новое (spec 075), зарегистрировано как expected failure с `source: spec-075`:**

| Новое | Где | Почему это находка, а не дубль 074 |
|---|---|---|
| Шапка Paywall выше вьюпорта (−26…−188 px), обе кнопки | `Paywall.tsx:102` | В 074 измерялись только именованные узлы и сгиб; отрицательный `top` не проверялся. Механика (`justify-content: center` + переполнение) подтверждена отдельной пробой |
| `paywall-start-trial` за сгибом на 360–390 | `Paywall.tsx:267` | 074 знал про `paywall-buy`; вторая кнопка действия на узких ширинах не измерялась |
| `back-to-dashboard` ниже сгиба на 360–390 | `ExamResults.tsx:152` | Тот же класс, что CTA Results (074 L1), но конкретный узел на 640–720 высотах не измерялся |

Новые находки **не фиксились** (задание запрещает): они занесены в реестр
`KNOWN_ISSUES` (`e2e/layout-smoke.spec.ts`) с `source` и `file:line`, попадают в
JSON-замеры и в этот отчёт. Гейт зелёный именно на них; любое нарушение **вне**
реестра роняет тест списком.

## 7. Top-5 — капитану

1. **Paywall: шапка с «На главную» уходит ВЫШЕ вьюпорта** — `Paywall.tsx:102`,
   `top = −25.5 (412×915) … −187.8 (360×640)`. Кнопка недостижима ни прокруткой,
   ни тапом: экран открывается без видимой навигации. Причина — `justifyContent:
   'center'` у контейнера, содержимое которого выше вьюпорта. **High, новое.**
2. **Paywall: обе кнопки действия за сгибом на 360–390** — `Paywall.tsx:288`
   (`paywall-buy`, top 719–746 при высоте 640–720) и `Paywall.tsx:267`
   (`paywall-start-trial`, top 655–682). На 390×720 (реальная TMA-высота)
   основная кнопка покупки начинается ниже экрана. **High.**
3. **Exam results: «вернуться» ниже сгиба на 360–390** —
   `ExamResults.tsx:152`, `top = 795` при высотах 640/667/720. **High, новое.**
4. **Dashboard: «Продолжить» ниже 14 строк тем на всех размерах** —
   `Dashboard.tsx:800`, top 1904–1971. На возвращающегося пользователя это главный
   вход в занятие; в TMA его роль играет MainButton, вне TMA — прокрутка ~1200 px.
   **Medium-High, известно из 074.**
5. **`exam-cancel` 360×34 < 44 px** — `ExamRun.tsx:247`, все 5 размеров; токен
   `--touch-min` (`tokens.css:57`) не применён. **Medium, известно из 074.**

**Хорошее:** горизонтального overflow и обрезанного текста нет **ни в одной** из
55 комбинаций; CTA, которые чинили 070/071/072 (`next-button`, `exam-submit`,
`exam-start`, `analytics-back`), внутри вьюпорта везде.

## 8. Что дальше (вне этой спеки)

Фиксы — отдельные спеки (`type: ui`), по одному классу за раз, с прогоном
`e2e/layout-smoke.spec.ts` как приёмкой (после фикса соответствующая запись
`KNOWN_ISSUES` убирается, и тест обязан позеленеть сам, без `fixme`). Для шапки
Paywall минимальная правка — снять центрирование контейнера (`justifyContent`)
либо ограничить высоту контента; для CTA — вынести действие в фиксированный
футер (как сделано в 070 для экрана вопроса).
