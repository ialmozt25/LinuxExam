## Вопросы

### `fm_013` — rsync: синхронизация каталогов с удалением лишних файлов

- **topic:** `file_management` · **difficulty:** medium · **objective_domain:** `1`
- **question:** Какая команда синхронизирует содержимое каталога src/ в dst/, удаляя из dst/ файлы, которых больше нет в src/?

  - **A.** rsync -a --existing src/ dst/
  - **B.** rsync -a --backup src/ dst/
  - **C.** rsync -a --delete src/ dst/  ← **верный**
  - **D.** rsync -a --update src/ dst/

- **correct:** C
- **explanation:** Ключ --delete удаляет из приёмника файлы, отсутствующие в источнике, поэтому именно он даёт точное зеркало. Без него rsync -a только копирует новые и изменённые файлы, оставляя лишние. --update пропускает файлы, которые новее на приёмнике, ничего не удаляя. --existing не создаёт на приёмнике новые файлы, а --backup лишь переименовывает заменяемые, лишние файлы оба ключа не трогают.

### `fm_014` — dd: создание файла заданного размера

- **topic:** `file_management` · **difficulty:** easy · **objective_domain:** `1`
- **question:** Какая команда создаст файл disk.img размером 100 МБ, заполненный нулями?

  - **A.** dd if=/dev/zero of=disk.img bs=1M size=100
  - **B.** dd if=/dev/null of=disk.img bs=1M count=100
  - **C.** dd if=/dev/zero of=disk.img bs=1K count=100
  - **D.** dd if=/dev/zero of=disk.img bs=1M count=100  ← **верный**

- **correct:** D
- **explanation:** bs задаёт размер блока, count — их количество: bs=1M и count=100 дают ровно 100 МБ нулей из /dev/zero. Чтение из /dev/null не выдаёт данных, поэтому файл останется пустым. При bs=1K и count=100 получится только 100 КБ, а операнда size у dd нет — размер определяется только через bs и count.

### `fm_015` — split -b: разбиение файла на части заданного размера

- **topic:** `file_management` · **difficulty:** medium · **objective_domain:** `1`
- **question:** Какая команда разделит большой файл на части по 10 МБ каждая?

  - **A.** split -l 10M data.log
  - **B.** split -b 10M data.log  ← **верный**
  - **C.** split -c 10M data.log
  - **D.** split -n 10M data.log

- **correct:** B
- **explanation:** Ключ -b задаёт размер части в байтах (суффикс M означает мегабайты), поэтому split -b 10M делит файл на куски по 10 МБ. Ключ -l разбивает по числу строк, а -n — на заданное количество частей, поэтому значение 10M в них некорректно. Опции -c в GNU split нет — такая команда завершится ошибкой.

### `fm_016` — truncate -s 0: обнуление содержимого файла без удаления

- **topic:** `file_management` · **difficulty:** easy · **objective_domain:** `1`
- **question:** Какой командой очистить файл до нулевой длины, не удаляя его?

  - **A.** truncate -s 0 data.log  ← **верный**
  - **B.** rm --force -- data.log
  - **C.** truncate -s 100 data.log
  - **D.** touch -c -m data.log

- **correct:** A
- **explanation:** truncate -s 0 устанавливает размер файла в ноль байт, полностью очищая содержимое, но сохраняя сам файл и его inode. Команда truncate -s 100 оставит файл размером 100 байт, а не пустым. touch лишь обновляет метки времени, не трогая данные. Команда rm удаляет файл, что нарушает условие «не удаляя».

### `fm_017` — mktemp -d: создание безопасного временного каталога

- **topic:** `file_management` · **difficulty:** easy · **objective_domain:** `1`
- **question:** Какая команда безопасно создаст временный каталог с уникальным именем в /tmp?

  - **A.** mkdir -m 700 /tmp/tmp.$$
  - **B.** mktemp /tmp/tmp.XXXXXX
  - **C.** mktemp -p /tmp tmp.XXXXXX
  - **D.** mktemp -d /tmp/tmp.XXXXXX  ← **верный**

- **correct:** D
- **explanation:** mktemp -d создаёт каталог и заменяет XXXXXX случайными символами, что исключает коллизии и гонки. Без -d mktemp создаёт файл, а не каталог; ключ -p лишь задаёт базовый каталог, поэтому каталога тоже не получится. Команда mkdir с $$ использует PID вместо случайности и завершится ошибкой, если такой каталог уже существует.

### `fm_018` — basename / dirname: извлечение компонентов пути

- **topic:** `file_management` · **difficulty:** medium · **objective_domain:** `1`
- **question:** Какая команда извлечёт из пути /etc/ssh/sshd_config только имя файла?

  - **A.** basename /etc/ssh/sshd_config  ← **верный**
  - **B.** realpath /etc/ssh/sshd_config
  - **C.** dirname /etc/ssh/sshd_config
  - **D.** readlink /etc/ssh/sshd_config

- **correct:** A
- **explanation:** basename отбрасывает путь и возвращает последний компонент — имя файла sshd_config. Команда dirname, наоборот, вернёт каталог /etc/ssh. realpath выводит полный канонический путь, а не короткое имя. readlink работает только с символическими ссылками, а sshd_config — обычный файл.
