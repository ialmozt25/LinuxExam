## Инструкция фазы (источник: docs/spec-chain/skills/spec-enrich/SKILL.md)

**Исполнитель:** LLM-вызов (`phase: "5-semantics"`).
**Входы:** спека после Фаз 2–3; результаты Фазы 1 (FAIL, если правка была
разрешена капитаном) и Фазы 4; baseline score.
**Шаги:**

1. Найти **противоречия** между разделами (Цель ↔ критерии, «Что делаем» ↔
   edge cases, критерии ↔ «Что НЕ трогать»).
2. Найти **дубликаты** требований и критериев: дубликат либо сливается в
   один пункт с сохранением смысла, либо обосновывается как намеренный.
3. Проверить **stale cross-refs**: ссылки на несуществующие файлы,
   разделы, id задач, спеки.
4. Найти **vague terms** («быстро», «удобно», «надёжно», «и т.п.»,
   «оптимально»): каждый либо определён числом/командой/наблюдаемым
   эффектом в спеке, либо переписан измеримо.
5. Разобрать **«Открытые вопросы»**: закрыть, если ответ уже следует из
   текста спеки; иначе оставить с пометкой «требует approve капитана».
6. Проверить, что каждый критерий приёмки измерим командой или явным
   артефактом.

**Выход:** `<run-dir>/phase-5-semantics.md` (противоречие/дубликат/vague
term → место → предлагаемая правка), применённые правки, запись в
`run-log.jsonl`.
**Критерий завершения:** 0 противоречий; 0 stale cross-refs; 0 vague terms
без определения; каждый дубликат слит или обоснован; каждый критерий
приёмки измерим; счётчик правок зафиксирован.
**Режим отказа:** противоречие снимается только изменением Цели или
Критериев приёмки → **STOP** (решение капитана); неразрешимая
неоднозначность формулировки → **WARN** + запись в «Открытые вопросы»;
попытка «удалить мешающий критерий» → **hard-fail** + rollback.
