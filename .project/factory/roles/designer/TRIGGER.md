# TRIGGER.md — триггер роли Designer

**M6.0 Phase 4 (D4) · 2026-09-28.** Машинночитаемая часть — та же, что в
`.project/factory/roles.yaml` (источник истины по составу ролей). Здесь — состояние
триггера и что его срабатывание изменит.

```yaml
role: designer
trigger:
  human: "second UI task"
  check: null            # машинного условия нет: триггер РУЧНОЙ
fired: false
status: planned          # без изменений: триггер не сработал
preset: null             # пресет роли не создан
```

## Почему `fired: false`

- Канон из `roles.yaml` («Правила заполнения»): `check: null` — триггер **ручной**;
  центр обязан пометить это, а не изобретать псевдо-условие. «Вторая UI-задача» —
  счёт по факту, а не метрика в состоянии.
- На 2026-09-28 UI-задач, прошедших как самостоятельный контракт, **ноль**:
  `type_map` в `roles.yaml` направляет `ui` в `designer`, но первая UI-задача, по
  исходному решению, решается Orchestrator'ом. Поэтому счётчик стоит на нуле,
  а не «почти сработал».
- Роль остаётся `planned`, артефакты в этом каталоге — **подготовка** (SKILL / DOD /
  TRIGGER), а не признак активности.

## Что срабатывание изменит (и чего не изменит)

**Изменит:**

- `roles.yaml`: `designer: planned → active` (правка капитаном; зеркало
  `state.json.roles[]` обновится через `npm run sync`).
- Здесь: `fired: true` + дата и кто зафиксировал.
- Секция «Роли» центра начнёт показывать Designer как активную роль, а `type_map`
  `ui → designer` перестанет вести к «роль не активна».

**Не изменит:**

- `preset` остаётся `null`: пресет — отдельное решение капитана и требует сброса DSH,
  а для первой активной UI-роли он не обязателен (прецедент `008`: роль существует
  документом).
- Границы роли: `src/data/**` — по-прежнему стоп (правило 6), persist/paywall —
  по-прежнему вне скоупа (контракт §4.2).

## Как проверить состояние триггера

- `roles.yaml` → `roles[designer].status` и `.preset` — источник истины.
- `state.json` → `roles[]` — зеркало (обновляется `npm run sync`; расхождение
  означает, что sync не прогнан).
- Центр `docs/index.html` → секция «Роли» (генерируется из `roles.yaml`).
