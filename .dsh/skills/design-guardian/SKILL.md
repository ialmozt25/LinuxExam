# design-guardian

Дизайн-контур LinuxExam. Контракт — `.project/governance/DESIGN.md`; этот скилл —
процедура его применения. Конфликт формулировок → Contract.

## Когда использовать
Любая правка UI: экран, компонент, стиль. Аудит экрана. Оценка дизайна. Перед релизом.
Если правка трогает `src/**/*.tsx` или `tokens.css` — скилл обязателен, а не опционален.

## Режим 1 — READ (перед кодом, обязательный)
1. Прочитай `.project/governance/DESIGN.md` — три ручки (variance/motion/density),
   доменные правила, anti-references.
2. Сформулируй Design Read в одну фразу:
   `Читаю <экран> как: <тип> для <аудитории>, с вайбом <...>, склоняясь к <...>`.
3. Сверь с DESIGN.md: попадает ли вывод в ручки (variance 4 / motion 2 / density 6)
   и не тянет ли в anti-reference (Notion / Vercel / Duolingo).
4. Только после Design Read — код.

Design Read — не ритуал, а решение: он отвечает, ЧТО за экран, ДО того как выбрана
сетка. Без него любая правка превращается в «сделай красиво».

Пример:
`Читаю экран quiz как: тренажёр-тест для RHCSA-кандидата, с вайбом терминала,
склоняясь к плотному одностолбцовому потоку и одному accent на действие.`

Признак плохого Design Read: если фраза подходит любому проекту — это не read.

## Режим 2 — BUILD
Токены:
- Трёхуровневые: global (примитивы) → semantic (роли) → component.
- Именование по назначению: `--color-action-primary`, не `--color-blue-500`.
- Hex запрещён в `.tsx`. Единственный источник — `src/presentation/theme/tokens.css`.

Компоненты:
- Atoms в `src/ui/`. Варианты отделены от состояний (variant ≠ hover/disabled).
- Composition через `children`, не через проп-флаги.
- Общие Badge/Button/Card не дублируются на экранах — импортируются.

Spacing:
- 4pt grid через `var(--space-*)`: 4 / 8 / 12 / 16 / 24 / 32.
- px-литералы для отступов запрещены; новый шаг — сначала токен, потом код.

Типографика:
- Шкала 1.25, один sans-стек. Иерархия через weight/size.
- `--text-*` / `--body` / `--heading-*`, не `fontSize: 18`.

Цвет:
- Один accent (`#1565C0`). `--color-accent-strong` — тот же accent, не второй.
- Dark mode: не `#000`; desaturated и cool-shifted, фон `#1E1E1E`/`#2D2D2D`.

Radii:
- 4px компактно, 8px карточки. Не 16px+ на большинстве поверхностей.

## Режим 3 — REVIEW (4 персоны, независимые проходы)
Четыре персоны, у каждой свой взгляд и свой проход. Персоны независимы: не видят
находок друг друга (иначе второй проход повторяет первый и «ААА, всё сломано»
превращается в один общий вердикт). Модель не оценивает свою работу.

1. **Art Director** — иерархия, композиция, типографика, визуальный ритм.
   Сверяет с DESIGN.md: ручки, anti-references, один accent.
2. **Production Engineer** — overflow, truncation, edge cases (длинные тексты,
   пустые состояния, 5-state форм), performance.
3. **Accessibility Auditor** — WCAG AA, focus, ARIA, keyboard, tap-targets.
4. **Product Critic** — понятность CTA, группировка, когнитивная нагрузка,
   «хорошо издалека, плохо вблизи».

Формат находки:
`severity (P0/P1/P2) | персона | файл:строка | проблема | рекомендация`

Сводка: `score /10` по персоне + топ-3 исправления.
Не «сделай красиво» — только конкретика (файл, свойство, значение).

Дисциплина ревью:
- P0 — блокирует: сломанный сценарий, недоступный контрол, нечитаемый текст.
- P1 — чинить до релиза: шум, конкурирующие CTA, ломающийся на 390 layout.
- P2 — долг: ритм, мелочи выравнивания, вкусовое.
- Находка без рекомендации с файлом/свойством/значением — не находка.
- Каждая персона проходит экран целиком, самостоятельно.
- Спор персон решает Contract (DESIGN.md), не «мнение мажоритарно».

## Anti-slop (перед коммитом)
```
node scripts/fitness/check-slop.mjs   # 0 violations
npm run typecheck                     # 0
npm run test:run                      # 0
npm run build                         # 0
```
Скриншоты 390 / 768 / 1200. Проверка глазами на реальном телефоне (FASB-001):
в эмуляторе верстка врёт, липкий футер и visual viewport видно только вживую.
12 tells перечислены в DESIGN.md → «Do's and Don'ts»; расшифровка — в
`scripts/fitness/check-slop.mjs` (tell-id в каждой находке).
