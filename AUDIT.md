## 4. Проблемы логики и архитектуры

### Высокий приоритет

**F-1. Доверие к флагу `isCorrect` из вызывающего кода**
`src/store/quizStore.ts:26,59-71` — `answerQuestion(questionId, selectedIndex, isCorrect)` принимает
вердикт правильности извне, вместо вычисления его из `Question` (`option.correct`).
Прогресс и статистика становятся недостоверными при ошибке в UI или при вызове стора в обход.
Правильно: вычислять правильность в domain-функции.

**F-2. `calculateProgress` считает неверный знаменатель**
`src/domain/quizService.ts:7-11` — делит число правильных ответов на **общее число вопросов**
(`questions.length`), а не на число отвеченных. При ответе на 1 из 5 верно → 20 %, хотя пользователь
ответил верно на 100 % доступного. Метрика «прогресс прохождения» смешана с «долей верных ответов».

**F-3. Нет тестов и тест-раннера**
Файлов `*.test.*` / `*.spec.*` нет; vitest/jest/testing-library не установлены.
Domain-слой состоит из чистых функций и идеально тестируем, но не покрыт. CI отсутствует.

### Средний приоритет

**F-4. Пейволл фактически недостижим (данные и логика рассинхронизированы)**
`FREE_QUESTION_LIMIT = 20` (`quizStore.ts:15`) при всего 5 вопросах в базе.
`canAccessQuestion(i)` всегда `true`, `nextQuestion()` никогда не выставит `isPaywallVisible`.
Экран оплаты невозможно даже увидеть.

**F-5. `isPro` хранится в localStorage и разблокируется без проверки оплаты**
`quizStore.ts:95-98,123-127` — `unlockPro()` просто ставит `isPro: true`; значение персистится.
Платный контент обходится правкой localStorage в один шаг. TODO(payments) честно это признаёт,
но для монетизации нужен серверный признак подписки.

**F-6. Небезопасные касты при загрузке данных**
`src/data/repositories/QuestionRepository.ts:14` — `questionsData as QuestionJson[]`;
`src/data/models/Question.ts:30-31` — `raw.topic as Topic`, `raw.difficulty as Difficulty`.
JSON не валидируется: опечатка в `topic`/`difficulty` даст невалидную `Question` без единой ошибки.
`strict: true` такие `as`-касты не ловит — нужна runtime-валидация (zod/ручной guard).

**F-7. Асинхронная по смыслу загрузка объявлена синхронной**
`quizStore.ts:50-57` — `loadQuestions()` синхронна, `isLoading` выставляется и снимается в одном
тике. Ветка `<p>Загрузка вопросов…</p>` в `App.tsx:22-23` практически не отрисовывается.
При переходе на fetch/ленивую загрузку JSON статус перестанет работать.

**F-8. `typecheck` не покрывает конфиги**
`npm run typecheck` = `tsc --noEmit -p tsconfig.app.json`, где `include: ["src"]`.
`vite.config.ts` входит в `tsconfig.node.json`, но этот проект нигде не проверяется;
`tsconfig.json` имеет `files: []` без `composite`. `tailwind.config.js`, `eslint.config.js`,
`postcss.config.js` вне TypeScript-проверки целиком.

### Низкий приоритет

**F-9. Несогласованность архитектурных границ**
README/AGENTS.md заявляют 4 слоя; по факту 2 рабочих плюс стор.
`src/main.tsx:3` импортирует `./App.tsx` относительным путём, тогда как весь остальной код
использует алиас `@/` (объявлен и в `tsconfig.app.json:17-21`, и в `vite.config.ts:8-12`).
Слой `data` импортирует тип `Topic` из `data/models`, а не из отдельного ядра — приемлемо,
но стоит зафиксировать конвенцию направления зависимостей.

**F-10. Коллизия имён**
`quizStore.ts:6` импортирует селектор `getCurrentQuestion`, а в состоянии есть метод с тем же
именем (`:112-114`). Читается тяжело; помогает алиас при импорте.

**F-11. Косметика и гигиена**
- `package.json:2` — имя `vite-react-typescript-starter` вместо `linuxexam`.
- `README.md` — 3 строки, только ссылка на Bolt; нет инструкции запуска, описания архитектуры и статуса.
- Нет `engines` в `package.json`, хотя в задаче зафиксировано требование к Node.
- `npm run build` выдаёт предупреждение об устаревшем `caniuse-lite` (не ошибка).
- Сборка оставила `dist/` — он в `.gitignore`, репозиторий не загрязнён.
